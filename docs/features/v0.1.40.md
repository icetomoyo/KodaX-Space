# KodaX Space v0.1.40 — KodaX 0.7.86 Sandbox and Owner-Reconciliation Release

> Status: Release candidate; finalized after the v0.1.40 tag and GitHub release gates complete.
> Date: 2026-08-14
> Source of truth: this file, the [release-readiness record](../releases/v0.1.40-release-readiness.md), the capability ledger, and the current tests.

## Release intent

v0.1.40 packages the already-landed KodaX 0.7.86 compatibility line. It is a
runtime safety and packaging maintenance release, not a new product workflow.
The Space manifests and lockfile resolve one exact npm Registry package, and
Coder refuses to start against a Runtime that cannot negotiate the required
sandbox contract.

## KodaX 0.7.86 and sandbox v3

Both the root and Desktop manifests use the exact published
`@kodax-ai/kodax@0.7.86` bytes. The lockfile integrity is:

```text
sha512-6xYcn97r2Q5XKlxMbUZivt/4e3M+2WXfYfV8N4ffgLECxGZrX+tQut7Cmzt7eR3jF36/VLrElUadLBrUD8Lepw==
```

Coder startup now requires `sandboxRuntime:3` from both the SDK probe and the
connected Runtime. An older v1/v2 daemon is not silently reused for a new
Coder owner; the SDK's verified capability-upgrade path must retire it first.
The Settings Runtime panel and the capability ledger expose the same status.

Sandbox v3 is sandbox-first for Runtime Shell. When containment is ready, the
command runs inside the contained runner. When containment cannot be prepared,
an already-authorized command follows the existing normal permission policy
without replaying the command or making a second classifier decision. Hard
denials for destructive control-plane operations remain unchanged.

## Packaged Windows and Issue 128

The KodaX 0.7.86 line repairs the packaged Electron/ASAR Windows Shell chain.
The release smoke covers the standalone sandbox doctor, a real contained marker
command, daemon-side `sandboxRuntime:3` negotiation, and a daemon shell probe
before and after a restart. The helper path remains physical and staged outside
the ASAR archive where the SDK requires it.

## Daemon owner reconciliation

Daemon startup delegates readable inline-owner reconciliation to the SDK's
atomic daemon-enable operation. A provably abandoned inline owner can recover
without deleting `~/.kodax`; active, unreadable, malformed, or unverifiable
ownership remains fail-closed. Space retains an inline owner handle when close
fails and retries release, so a transient cleanup error cannot silently orphan
the ownership fence.

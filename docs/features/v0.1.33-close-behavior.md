# v0.1.33 Configurable Main-Window Close Behavior

> Status: Released in `v0.1.33`
> Release date: 2026-07-27
> Parent design: [v0.1.33 Runtime Stabilization and Desktop Control](v0.1.33.md)

`v0.1.33` uses its maintenance capacity to make the Windows background-runtime
lifecycle introduced by F136 explicit and user-configurable. The change does
not alter Runtime ownership or weaken the existing safe daemon-stop gate.

## FEATURE_140: Configurable Main-Window Close Behavior

### 1. Requirement summary

When the user closes the main KodaX Space window, Space must either:

- remove the main window while retaining the notification-area owner and daemon;
- request a complete Space exit and safely stop an idle, unshared daemon; or
- ask which of those actions to perform.

Profiles without an effective preference default to asking on the first close
attempt. The prompt offers **Remember my choice**. Choosing an action with that
checkbox enabled persists the action for later close attempts. Cancelling does
not close the window or change the preference. Settings exposes all three
states so the user can change or reset the behavior at any time.

### 2. Impact scope

- Space settings schema, migration/default projection, persistence, and typed IPC.
- Windows main-window close lifecycle and the existing background tray owner.
- Preferences UI and `zh-CN` / `en-US` copy.
- Unit coverage for schema, persistence, prompt-result mapping, and close-policy
  resolution.

The original preference remains Windows-only, but the corrected lifecycle now
changes every real application quit: macOS Cmd+Q, Linux last-window exit, and
Windows complete exit share one fail-closed daemon-stop contract. Runtime
blockers and the no-force-stop policy are unchanged.

### 3. Technical design

- Persist `windowCloseBehavior` as one of `ask`, `minimize-to-tray`, or
  `quit-completely`; missing and invalid legacy values normalize to `ask`.
- Intercept user-driven main-window close events only while a usable Windows
  tray exists. App shutdown and OS session-ending paths bypass the preference.
- Resolve the configured action in the Electron main process so renderer
  crashes, Alt+F4, and the custom title-bar close control share one policy.
- Serialize close decisions so repeated clicks cannot open multiple prompts or
  race window destruction with complete-exit preflight.
- Use a one-shot bypass when Space intentionally closes the BrowserWindow to
  the tray, preventing the synthetic second close from re-entering the policy.
- Reuse F136 `requestCompleteExit`, but close Coder admission before preflight.
  Inspect both Runtime-owned work and Space-local Partner sessions, local
  Workflow runs, permission/AskUser requests, queued prompts, and external
  Agent tasks; any blocker keeps Space visible.
- Remove the tray action that exited Electron while preserving a Space-started
  daemon without a visible owner.
- While the Runtime client and visible control surface still exist, commit the
  daemon's revision/owner-policy-fenced `stopForInline` transaction, wait for
  owner release, hold a temporary inline fence, restore daemon policy, and
  verify the profile is unowned. Only then may Electron tear down local
  resources. The CLI `missing` result is not proof by itself; it is accepted
  only when the independent owner-state read is unowned.
- A CAS conflict, blocker, unreadable/owned state, stop failure, or timeout
  keeps Space visible. If owner-policy recovery itself requires a process
  restart, Space registers one visible recovery relaunch before exiting.
- Pass `daemonOrphanExitMs=30000` to KodaX auto-start and require the returned
  daemon to advertise `daemonOrphanExit:1`. A daemon that loses
  its final client waits for governed work to become idle, then self-stops;
  other clients and ordinary CLI persistent daemons are preserved.

### 4. Interface contract

- `SpaceSettingsT.windowCloseBehavior: WindowCloseBehaviorT`
- `settings.setWindowCloseBehavior({ windowCloseBehavior }) -> SpaceSettingsT`
- Prompt responses:
  - **Minimize to tray**: close the BrowserWindow, preserve tray and Runtime.
  - **Quit completely**: enter the existing safe complete-exit flow.
  - **Cancel / dialog dismissal**: preserve the current window and preference.
- **Remember my choice** writes only `minimize-to-tray` or `quit-completely`;
  the Settings UI can explicitly restore `ask`.

### 5. Implementation steps

1. Add schema, channel registration, store normalization, and atomic setter.
2. Add failing schema/store/decision tests, then implement the pure decision
   model.
3. Install the guarded close handler in `main.ts` and keep explicit tray menu
   actions independent.
4. Add the Preferences selector and localized copy.
5. Run targeted tests, full workspace tests, typecheck, lint, and build smoke.
6. Perform an independent code review and repair validated findings.

### 6. Acceptance criteria

- A clean or legacy profile sees one close-choice prompt on the first
  user-driven close attempt while the Windows tray is available.
- Cancelling keeps the main window open; repeated close clicks while the prompt
  is pending do not create duplicate dialogs.
- Either action executes once without persistence when **Remember my choice**
  is clear.
- Either action is persisted before execution when **Remember my choice** is
  checked, and later close attempts execute directly.
- Settings can select all three states and survives restart.
- Minimize-to-tray preserves the daemon and a usable tray entry that can recreate
  the window.
- Complete exit retains F136 safety behavior and never force-stops active work
  or a daemon held by another client.
- macOS Cmd+Q and Linux quit use the same gate; blocker or stop failure cannot
  leave an invisible daemon without a Space window/tray.
- A Space process crash is covered by the daemon's opt-in idle orphan reaper.
- The current orphan capability proves opt-in idle-only policy, not a
  configurable grace value or verified retry after an asynchronous host-close
  failure. Packaged qualification must observe actual PID/lock/state removal;
  a KodaX-side retry/terminal-failure contract remains necessary before this is
  treated as complete crash cleanup on every platform.
- Explicit tray commands, application quit, OS session end, and tray-disabled
  fallback do not enter the Windows close-choice prompt, but real quit still
  enters complete-exit coordination.

### 7. Completion evidence

- The typed settings contract, main-process close policy, localized Preferences
  selector, and Windows tray lifecycle integration are implemented in current
  source.
- Independent review found two SettingsStore transaction defects: concurrent
  setters could overwrite unrelated fields, and a failed atomic replacement
  could expose an unpersisted cached value. Both are fixed and have regression
  tests.
- The serial Electron suite passes 1,764 tests with two platform skips; targeted
  close/settings/manifest tests, typecheck, lint, build smoke, and both Windows
  close-preference/tray Playwright scenarios pass.
- Native-dialog interaction and Runtime-blocker cases remain explicitly covered
  by the [F140 human test guide](../test-guides/FEATURE_140_v0.1.33_TEST_GUIDE.md)
  because Playwright cannot reliably drive Electron's operating-system dialog.
- The 0.7.78 follow-up adds revision-fenced pre-teardown stop, independent owner
  verification, and Space-local blocker coverage. F140 remains In Progress
  until packaged macOS/Linux complete-exit and orphan PID-removal journeys pass.

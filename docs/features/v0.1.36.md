# KodaX Space v0.1.36 — Session and Runtime Reconciliation Hardening

> Status: Released 2026-08-05
> Scope: maintenance release; no new numbered Feature is assigned.
> Source of truth: this file, the [release-readiness record](../releases/v0.1.36-release-readiness.md), and the current tests.

## Version outcome

`v0.1.36` turns the post-`v0.1.35` session-integrity fixes into the current
public baseline. The package version is `0.1.36` and every formal workspace
manifest is aligned with the exact npm Registry `@kodax-ai/kodax@0.7.82`.

The release is intentionally a stabilization slot. F137 and F139 remain
scheduled for [v0.1.42](v0.1.42.md); this release does not claim the native
document Skill suite or semantic UI polish.

## Delivered scope

### Active Session input admission

Send, interrupt, after-turn, draft restoration, Session switching, and
history revalidation share one bounded admission boundary. A Session topology
change cannot race a fresh input and turn a transient `data_changed` or
stale snapshot into a user-visible generic handler failure.

### Exact live/history ownership

Accepted inputs retain their exact `runId` and streamed `turnId`. Runtime event
identity, canonical history boundaries, paging cursors, and snapshot
watermarks are preserved through reconnect, Session switching, scrolling, and
late history reads. Space does not use message text, position, or a stale
activity snapshot to guess ownership or completion.

### Renderer recovery and isolation

Session hydration, sidebar activity, live transcript projection, and history
paging now reject events from another Session and reconcile stale snapshots
without losing an in-flight transcript. Restore, fork, interrupt, and
concurrent Session paths have focused regression coverage.

### Published dependency and manual alignment

Root/Desktop manifests, both workspace lock views, installed package bytes,
release gates, capability reporting, the user manual, and the injected
`kodax_manual` all describe KodaX 0.7.82 and the v0.1.36 session boundary.
The manual continues to inherit the SDK's underlying mechanism topics instead
of maintaining a stale copied SDK manual.

## FEATURE_032 v2: 流内提问卡（替换全屏模态）

### 1. 需求概述

`ask_user_question` 与 guardrail 授权从全屏遮罩模态（AskUserModal，已删除）改为「混合方案」内联交互，对齐业界收敛形态（Claude Code / Cursor / VS Code Copilot / Cline / Gemini CLI 均为流内提问 + 折叠终态 + 轻量召回 + 键盘可达）：

- 问题/授权卡渲染在对话流尾部（紧贴上下文），对话历史全程可滚动，无遮罩。
- 全部 pending 卡并存且均可点选作答（每 reqId 独立 `askUser.reply` IPC 结算）。
- composer 上方常驻停靠召回条：计数徽标 + 队首摘要 + 「查看」滚动定位闪光；右侧栏 max 模式下由 Shell 根节点兜底渲染同一条。
- 键盘（仅队首卡）：1-9 快选、Enter 提交/允许、Esc 取消/阻止。

### 2. 影响范围（纯 renderer，零 SDK/IPC/主进程改动）

- 新增 `apps/desktop/renderer/src/features/ask-user/AskUserInline.tsx`：`AskUserInlineStack`（ConversationStreamV2 消息尾部）+ `AskUserDockBar`（BottomBar RetryBanner 后；Shell max 模式兜底）+ `AskUserInlineCard`（select 单/多选/min/max/自定义输入/back 信号/input/multi 逐题/guardrail signals+诊断+输入预览）。
- 新增 `askUserQuestionRules.ts`（原 modal 校验逻辑原样抽出的纯模块）+ 单测 10 用例（node:test 直跑，锁住协议语义：`min_selections:0` 可空提交 FEATURE_222、自定义输入必填、全局 20 上限、真实 min 优先报错等）。
- 删除 `AskUserModal.tsx`（-598 行）；`Shell.tsx` 移除模态挂载、新增 max 模式召回监听；`ConversationStreamV2.tsx` 渲染 Stack、搜索框加 `data-testid="transcript-search-bar"`；`i18n/messages.ts` +4 键×双语。

### 3. 键盘协议（四层让位 + 独占消费）

window 冒泡监听仅队首卡注册，按键依次让位：

1. `defaultPrevented` / 修饰键 / `event.repeat` / 焦点在 `input, textarea, select` 或 contentEditable；
2. 任何 FloatingSurfaceHost 浮层打开（`[data-floating-surface-host]`，即 PermissionModal/ConfirmDialog/popout）；
3. 任何 ARIA 浮层（`[role="dialog"], [role="alertdialog"], [role="menu"], [role="listbox"]`）或 transcript 搜索框打开；
4. 作用域门控：焦点在 `[data-testid="conversation-stream"]` 内或 body 上才接管（结构性避开 BottomBar 芯片菜单、ModeSelector 数字键、命令面板等 window 级监听）；
5. 焦点在另一张 `[data-ask-user-req]` 卡内时让位（键盘只归队首卡，防错误归属提交）。

通过后 `preventDefault + stopImmediatePropagation` 独占。数字键映射排除 back 信号（无角标、不可逆）；角标编号 = 过滤后序列号，上限 9。

### 4. 滚动与召回

- 新卡到达不主动滚动：贴底场景由 ConversationStreamV2 ResizeObserver 追底权威处理（`wasAtBottomRef`），用户上翻历史零打扰。
- 停靠条「查看」→ `kodax-space.focus-ask-user` 事件：Shell 若处 max 模式先退出（`setRightSidebarWidthMode('default')`），Stack 隔两帧 instant 滚动定位队首卡 + 聚焦首个控件 + 900ms 闪光（定时器有 cleanup）。

### 5. 验收标准

- select/input/multi/guardrail 全形态可答，答复语义与旧 modal 逐行一致（rules 单测锁定）。
- Pending 卡到达时对话流可自由滚动/搜索；Dock 计数与队列一致，全部处理完自动消失。
- ConfirmDialog/PermissionModal/Settings/QuickAsk/命令面板/搜索框打开时按 Enter/Esc/数字只作用于该浮层，不会同时提交/取消问题卡。
- 焦点在第 2+ 张卡内按 Enter 不会提交队首卡。
- 右侧栏 max 模式：窗口底部中央出现兜底召回条，点「查看」退出 max 并定位到队首卡。
- `npx tsc -p apps/desktop`、`tsc -p apps/desktop/electron` 本特性文件零错误；rules 单测 10/10。

### 6. 已知边界（有意决策）

- 待答持久化语义不变：待答在 runtime askUserBroker（观察快照重水合）、已答进 transcript tool_call、超时由 `expiresAt` 数据驱动（UI 无定时器）。
- composer 在 pending 期间可自由发新消息（旧模态屏蔽期不可能）——runtime ask-and-wait 对并发用户消息的处理属行为面变化，需 main 端确认。
- 卡片本地草稿（选项/自定义输入）切会话即失——与旧 modal 等价，不算回归。
- 滚动锚点测量对卡片是盲区（卡无 `data-msg-id`）：短会话+高卡+顶部上滚触发分页的组合下走 ratio/seam 兜底，不新增标记。
- e2e 无内联卡冒烟覆盖（现存 e2e 从未覆盖 ask-user UI）；键盘归属/双消费场景建议后续补 e2e。

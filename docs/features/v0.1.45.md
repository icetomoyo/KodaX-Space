# v0.1.45 - Learning Center Desktop Host

> Status: Planned / SDK-gated
> Feature: F118
> Hard gate: published KodaX KX-F266 `runtime.learning` capability
> Additive gates: KX-F263 Skill learning and KX-F264 Extension learning actions

## Batch decision

Space will host one KodaX-owned Learning Center. It will not build a Skill-only proposal queue, duplicate the F224 learning store, or invent a Workflow learning loop.

KX-F266 defines the lifecycle, durable events, human-readable identity, per-client notification cursors, Runtime ownership, and transport-safe service. KX-F263/F264 later add carrier-specific review/trust/test actions. Space renders and controls only advertised actions.

## FEATURE_118: Learning Center Desktop Host

### User outcome

Users have one searchable place to understand learned behavior and control it by name:

- opportunity/drafting/ready state;
- active learned capability and provenance;
- review/trust/test status;
- disable, rollback, archive/restore, reject, snooze, and promote actions;
- quarantined failures and previous-good revision;
- whether the carrier is Memory, Skill, or Extension.

### SDK contract gate

Before implementation, verify the released Runtime exposes capability-negotiated equivalents of:

- list/page/query and get by human name/slug;
- event subscription/replay and per-client notification cursor;
- acknowledge/snooze/reject/disable/rollback/archive/restore/promote;
- carrier-specific review/trust where registered;
- owner identity and inline/Worker/daemon parity;
- `learningCenter`, `skillLearningLoop`, and `extensionLearningLoop` capability flags or their released equivalents.

Unsupported actions fail explicitly. Space never infers action support from lifecycle text or an SDK version.

### UX

- Add a Learning Center popout reachable from Environment Hub/Task Dock and `/learn open`.
- Use human display name/slug as the primary identifier; opaque IDs remain diagnostic only.
- Views:
  - **Ready**: decisions requiring user review/trust;
  - **Active**: learned Skills/Extensions currently usable;
  - **Opportunities**: quiet evidence records, no badge by default;
  - **Quarantined**: attributable failures and safe-state status;
  - **History**: bounded durable lifecycle events.
- Persistent badges reflect unread/attention state, not total record count.
- Reading/acknowledging a notice cannot approve or trust code.
- Learned Extension review shows exact source/schema/effects/tests/fingerprint before trust.
- Formal promotion clearly transfers ownership to the user's normal catalog and checks collisions.

### Carrier boundaries

| Carrier   | Space presentation                                                      | Authority boundary                                             |
| --------- | ----------------------------------------------------------------------- | -------------------------------------------------------------- |
| Memory    | Link to F117/F088 governance and evidence                               | Durable changes through F228 governance                        |
| Skill     | Diff, rationale, evidence, version, activate/disable/rollback/promotion | KodaX learned Skill store; lower precedence than formal Skills |
| Extension | Exact source, schemas/effects, independent tests, quarantine/rollback   | No code runs before trust; Runtime owner tests/installs        |
| Workflow  | History/unsupported carrier only                                        | Workflow remains generated execution, not a learned carrier    |

### Runtime ownership

- Inline/Worker/daemon Runtime owner performs writes, review jobs, tests, install, reload, and rollback.
- Space is a client with a stable client identity and its own unread cursor.
- Multiple clients share lifecycle state but not notification read state.
- Persist state and event before emitting; reconnect uses event cursor.
- Renderer never receives file paths or controller instances as authority.

### Security

- Generated Extension code never runs before an explicit supported trust action.
- Worker isolation is not described as a security sandbox.
- Learned Extensions use a visible namespaced deferred tool surface until formal promotion.
- Learned Skills cannot shadow formal builtin/plugin/project/user Skills.
- Candidate self-report, invocation count, or confidence cannot prove correctness.
- A safe previous revision remains active when a new candidate fails.
- Store corruption or rollback failure is a Runtime integrity error and disables learned activation fail-closed.

### Explicit non-goals

- No Space-owned learning store, reviewer, code generator, curator scheduler, or lifecycle engine.
- No Workflow learning, global prompt mutation, model training, or silent formal promotion.
- No learned slash command before explicit formal promotion support.
- No toast for every opportunity, invocation, or handled failure.

### Acceptance

- List/detail/event/action behavior passes against every Runtime form advertised by the released SDK.
- Restart/reconnect restores unread decisions without duplicate jobs.
- A second client has an independent notification cursor and shared lifecycle result.
- Review and trust are visibly separate; reading cannot execute code.
- Disable/rollback/quarantine/promotion preserve audit and previous-good state.
- F263/F264 absent: the center still works for F224/F228-compatible records and clearly marks unsupported carrier actions.

### Rollout and rollback

- Gate the entire surface on `learningCenter` capability.
- Gate Skill and Extension action groups independently.
- Rollback disables learned activation/actions while preserving read-only history and formal user-owned catalogs.

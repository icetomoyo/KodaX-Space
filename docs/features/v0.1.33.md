# v0.1.33 — Runtime Stabilization and Desktop Control

> Status: Released
> Release date: 2026-07-27
> Product version: `0.1.33`
> KodaX baseline: exact npm-published `@kodax-ai/kodax@0.7.77`
> Release evidence: [v0.1.33 release readiness](../releases/v0.1.33-release-readiness.md)

## 1. Release goal

`v0.1.33` is the stabilization release after the enlarged `v0.1.32` shared-daemon, Partner knowledge, parser/citation/retrieval, exact-history and Windows background-runtime baseline. It does not introduce a new product surface or move Partner into the Coder daemon. It makes existing ownership, replay, diagnostics, attachments and desktop lifecycle behavior deterministic enough for daily use.

The release has five outcomes:

1. KodaX Space and every workspace package report `0.1.33`, while both Runtime-consuming workspaces use the exact Registry `@kodax-ai/kodax@0.7.77`.
2. Runtime-backed Coder state is canonical and monotonic: root history, live events, Agent Actor trees, pending input and terminal state do not duplicate or replace one another.
3. Context pressure, cumulative Provider usage and prompt-cache routing are separate, privacy-safe facts.
4. Terminal and Coder command tools use one selected Shell/profile-PATH contract, while F140 makes main-window close behavior explicit and configurable.
5. Clipboard images, persisted Session ownership, resume/delete/dispose and dense Task/Agent presentation remain bounded under recovery and long-running use.

## 2. Release scope

### 2.1 Runtime, Agent and transcript stabilization

- Consume the complete KodaX 0.7.77 physical-request diagnostic stream and deduplicate by `requestId`.
- Preserve the root context projection while exposing bounded recursive native, constructed, Workflow and external Actor/Turn state.
- Fold durable history and live Runtime events by canonical Turn identity.
- Retain Runtime-only lifecycle, tool, Todo, Artifact, context and notice events without duplicating durable text.
- Fence persisted-session cache reads against concurrent mutation.
- Make resume, delete and dispose single-flight and reject stale completion after a lifecycle generation changes.
- Let authoritative Runtime running/terminal projections clear stale pending-send and legacy activity state.

### 2.2 Context, usage and cache diagnostics

- Use the final automatic-compaction threshold as the effective context denominator.
- Keep model maximum context, automatic-compaction threshold and output reserve as independent facts.
- Expose a content-free six-part latest root request composition.
- Accumulate root and child physical Provider calls separately from the root context gauge.
- Carry only the hash-form cache-affinity identity through Space IPC.
- Keep custom Provider cache affinity opt-in and default-off.

### 2.3 Shell, terminal and desktop lifecycle

- Offer Auto, PowerShell 7, Windows PowerShell and cmd on Windows without accepting arbitrary executable paths.
- Use platform-safe login-shell discovery on macOS/Linux.
- Apply the selected Shell/profile PATH to new Terminal tabs and daemon-backed Coder command execution.
- Keep API keys, tokens and secrets outside the PTY allowlist.
- Deliver F140 ask/keep-in-tray/safe-complete-exit behavior and optional remembered choice.
- Preserve the existing F136 rule that Runtime stop is refused while active/queued/pending work or another client remains.

### 2.4 Attachments and dense UI

- Separate bounded clipboard source bytes from the normalized persisted image limit.
- Validate safe persisted Session ownership without eagerly creating Provider/Runtime state.
- Preserve canonical normalized media type and path across Session recovery.
- Cap Task/Agent scrolling and retain visible edge affordances and active-state emphasis.

## 3. Non-goals

## FEATURE_140: Configurable Main-Window Close Behavior

### 1. 需求概述

Users need the main-window close action to match their preferred desktop workflow without weakening the shared Runtime safety boundary. The supported choices are:

- ask on close;
- close the BrowserWindow and keep Space/Runtime available in the tray;
- request a complete exit through the existing safety-gated Runtime stop flow.

The ask flow may remember a choice. A remembered choice must remain editable in Preferences.

### 2. 影响范围

- `apps/desktop/electron/main.ts`
- `apps/desktop/electron/window/window-close-behavior.ts`
- `apps/desktop/electron/settings/store.ts`
- settings and window-close IPC schemas/handlers
- `apps/desktop/renderer/src/features/settings/SettingsModal.tsx`
- localized strings and close-confirmation UI
- unit tests, Electron E2E and the versioned human test guide

The feature does not change Runtime task ownership, daemon stop eligibility, tray ownership or the updater.

### 3. 技术方案

The settings store persists one closed enum: `ask`, `minimize-to-tray`, or `quit-completely`. Main resolves the effective action at the BrowserWindow close boundary. `ask` displays a renderer-independent confirmation owned by Electron main and can persist the selected choice only when the user explicitly requests it.

`minimize-to-tray` destroys the BrowserWindow/renderer and retains the existing visible tray owner. `quit-completely` enters the same F136 complete-exit path used by the tray: Space disconnects first, asks Runtime to stop, and leaves the daemon running when work or another client blocks the stop.

### 4. 接口契约

- `settings.get` returns the current `windowCloseBehavior`.
- `settings.setWindowCloseBehavior` accepts only the closed enum.
- No renderer-supplied executable, path, daemon identity or stop override crosses IPC.
- Window close never bypasses the Runtime daemon's active/queued/pending/other-client checks.
- On platforms or startup states without a usable tray, close falls back to an explicit ordinary-exit path rather than invisible residence.

### 5. 实现步骤

1. Add the enum to the shared settings schema and persisted settings store.
2. Register the settings IPC handler and include the entrypoint in the Coder action inventory.
3. Implement a pure close-decision helper and unit-test all choices.
4. Route the Electron close event through the decision helper and existing tray/complete-exit flows.
5. Add Preferences controls, localization and optional remember-choice UI.
6. Add Electron E2E and the human test guide.
7. Update README, user manual, injected `kodax_manual`, Feature List, changelog and release record.

### 6. 验收标准

- Ask mode presents the three truthful outcomes and does not close before the user decides.
- Remembering keep-running or complete-exit updates Preferences and affects the next close.
- Keep-running destroys the BrowserWindow and keeps a visible tray owner.
- Reopen creates a fresh functional window.
- Complete exit stops Runtime only when the safety gate permits it.
- Active/queued/pending work or another client keeps Runtime alive and produces a truthful result.
- Cancelling the prompt leaves the window usable.
- Unsupported persisted values migrate to `ask`.
- Unit, schema and Electron E2E tests pass.

The detailed F140 interaction record and manual journey remain in [v0.1.33-close-behavior.md](v0.1.33-close-behavior.md).

# v0.1.31 Implementation Plan - F116 Runtime Host Adapter

> Planning status: Implemented and released in `v0.1.31`
> Feature status: Completed
> Space baseline: `v0.1.30`, commit `2196bc0`
> KodaX contract baseline: F116 started on published `0.7.67`; final release resolves exact published `@kodax-ai/kodax@0.7.68`, source tag `v0.7.68`
> Prepared: 2026-07-12

## 1. Outcome

`v0.1.31` will introduce one Space-owned `RuntimeHostAdapter` in Electron main and move the live managed-run path onto the public inline KodaX Runtime facade without changing renderer IPC or user-visible Coder/Partner behavior.

The release is successful when:

- Runtime owns the KodaX session/run/event substrate used by new live turns;
- Space continues to own renderer projection, Partner policy/tools, permissions, AskUser, delivery/audit stores, and product-specific lifecycle;
- unsupported Runtime services are represented as explicit Space bridges or unavailable capabilities;
- no operation is executed by both the legacy and Runtime paths;
- the whole Runtime path can be disabled before process start without migrating or deleting user data.

This document is an execution plan. Product scope and non-goals remain in [v0.1.31.md](v0.1.31.md).

## 2. Verified starting point

### 2.1 Space implementation

The current integration is concentrated in three large layers:

| Area               | Current implementation                                                                | Observed constraint                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| In-flight host     | `apps/desktop/electron/kodax/host.ts` (`KodaXHost`, about 958 lines)                  | Owns session registry, resume, settings sidecar, list merge, fork, rewind, compact, cancel, delete, and title behavior. |
| Live run           | `apps/desktop/electron/kodax/real-session.ts` (`RealKodaXSession`, about 1,670 lines) | Builds every KodaX option/callback and calls `runManagedTask` directly.                                                 |
| Persisted sessions | `apps/desktop/electron/kodax/session-store.ts`                                        | Wraps the SDK session subpath and shares its storage handle with live runs.                                             |

There are 21 Electron-main files that reference the `kodaxHost` singleton. The public renderer boundary is already isolated behind `@kodax-space/space-ipc-schema`; this boundary must remain stable.

`RealKodaXSession` currently owns or binds all of the following and therefore cannot be replaced with a thin `runtime.runs.start()` call without a compatibility driver:

- Space `SessionEvent` translation and terminal-event de-duplication;
- PermissionBroker and AskUser bridges;
- Auto mode guardrails and plan-mode blocking;
- Partner `agentProfile`, tool visibility, sources, prompt overlay, and delivery tools;
- Space Extension Runtime lifecycle;
- workflow host policy and Workflow Controller attribution;
- External Agent Executor Plane binding;
- input artifacts, self-manual, repo-intelligence policy, compaction, provider/model/effort resolution;
- Space follow-up queue semantics and cancellation behavior.

### 2.2 Published Runtime contract

KodaX `0.7.67` exposes:

- `sessions`, `runs`, `events`, `permissions`, `workflows`, `config`, `catalog`, `mcp`, `artifacts`, `status`, and `diagnostics`;
- `admin.agentRegistrations`, `agents`, and `agentTasks`;
- inline and Worker embedded modes plus daemon connection;
- inline `RuntimeStartRunInput.options`, which can carry the existing function-valued `KodaXOptions` and `KodaXEvents` callbacks;
- Runtime event persistence, run status, session settings, and bounded replay.

The installed 0.7.67 package and tag implementation were checked directly for the initial F116 implementation. The final exact npm 0.7.68 package and matching source tag were then installed and tested without linking the sibling checkout. Its Runtime facade preserves the F116 contract and adds FEATURE_260 inside the managed coding path plus the `/experimental-memory` export.

### 2.2.1 0.7.68 compatibility slice

The 0.1.31 pre-adaptation is deliberately smaller than F117:

- probe `createMemoryAgent`, `createMemoryControlPlane`, and versioned `MEMORY_POLICY_VERSION` as required 0.7.68 release contracts;
- fail closed when the subpath is absent or its public shape is malformed;
- expose a truthful partial/planned capability row and diagnostic snapshot;
- attach lifecycle callbacks that log counts and categorical metadata only—never objectives, summaries, proposal IDs, evidence refs, or memory bodies;
- keep KodaX as the only Memory Agent/runtime owner and F228 as the only durable governance plane;
- leave Episodes, Activity, correction, forget, purge, and a runtime activation toggle to F117.

Release verification is strict against the 0.7.68 dependency declared in root/desktop manifests and the registry-resolved lockfile.

### 2.3 Contract gaps that shape this plan

| Gap                                                                                                                                                                                            | v0.1.31 decision                                                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Do not infer actions from the version string.                           |
| Runtime session settings do not contain Space `autoModeEngine`, `agentMode`, or the five-level abstract effort preference.                                                                     | Keep the Space session-runtime sidecar authoritative for Space-only settings. | With only `sessionsDir`, KodaX `0.7.67+` (including the final `0.7.68`) writes Runtime journal data below `<profile-root>/.kodax/runtime`.                                                     | Accept only after path-isolation tests for default, `KODAX_HOME`, `KODAX_PROFILE_DIR`, and onboarding-test roots. ## 3. Ownership model

The adapter is an ownership map, not a claim that every capability is Runtime-native.

| Capability                                                        | v0.1.31 owner                   | Adapter status | Notes                                                                                                       |
| ----------------------------------------------------------------- | ------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------- |
| Runtime identity/status/diagnostics                               | KodaX Runtime                   | `runtime`      | Inline identity and redacted status are authoritative.                                                      |
| Persisted transcript/compact/fork/rewind                          | KodaX Runtime                   | `runtime`      | Production selects one Runtime route for each migrated operation.                                           |
| Session list/resume/title/notices/archive/delete and cleanup      | Space compatibility projection  | `space-bridge` | Preserves surface/tag filtering, title overrides, sidecars, conflict behavior, and cleanup semantics.       |
| Empty in-flight session before first send                         | Space registry                  | `space-bridge` | Preserve current behavior; create/ensure the Runtime session before its first managed run.                  |
| Provider/model/thinking/permission/execution cwd                  | Space session state for v0.1.31 | `space-bridge` | Passed explicitly into each run. Runtime settings migration waits for exact semantic parity.                |
| Abstract effort, agent mode, auto-mode engine                     | Space session-runtime sidecar   | `space-bridge` | Not representable by the current Runtime session settings contract.                                         |
| Managed run lifecycle                                             | KodaX Runtime inline            | `runtime`      | `mode: 'managed_task'`; Space supplies the existing options and callback bridge.                            |
| Renderer session events                                           | Space                           | `space-bridge` | Existing `KodaXEvents -> SessionEvent` mapping remains the only renderer stream.                            |
| Rich event journal/replay                                         | KodaX Runtime                   | `runtime`      | Persisted for diagnostics and later F087/F090 use; not projected twice into the renderer.                   |
| Permission and AskUser decisions                                  | Space brokers                   | `space-bridge` | Runtime records waiting phases/events; Space callback remains authoritative.                                |
| Partner profile/tools/policy/deliveries                           | Space                           | `space-bridge` | Functions stay in the Electron owner process.                                                               |
| Extension Runtime                                                 | Space                           | `space-bridge` | Existing per-session lifecycle remains until a transport-safe contract exists.                              |
| Workflow lifecycle/list/get/library/origin/result/artifacts/admin | Space Workflow Controller       | `space-bridge` | Preserves immediate stop projection, reason, durable merge, attribution, extended lifecycle, and artifacts. |
| MCP server processes/logs                                         | Space MCP Manager               | `space-bridge` | Runtime must not start a duplicate server.                                                                  |
| External Agent plane/store                                        | Space ExternalAgentGateway      | `space-bridge` | Runtime plane remains disabled in the shared host for this version.                                         |
| Runtime Worker/daemon                                             | none                            | `unavailable`  | Explicitly out of scope for `v0.1.31`.                                                                      |

## 4. Target architecture

```text
renderer
  -> existing zod IPC
  -> RuntimeHostAdapter (process singleton)
       -> SpaceSessionRegistry (existing KodaXHost behavior)
       -> RuntimeOwner
            -> createKodaXRuntime({ mode: 'embedded', isolation: 'inline' })
            -> sessions / runs / events / workflows / status / diagnostics
       -> ManagedRunDriver
            -> runtime driver (default after gates pass)
            -> legacy runManagedTask driver (process-start rollback only)
       -> Space bridges
            -> PermissionBroker / AskUserBroker
            -> Partner profile/tools/stores
            -> Extension Runtime
            -> Workflow Controller extended operations
            -> MCP Manager
            -> ExternalAgentGateway
```

### 4.1 Proposed internal interfaces

The exact TypeScript may change during TDD, but responsibilities must stay separated.

```ts
type HostCapabilityOwner = 'runtime' | 'space-bridge' | 'legacy' | 'unavailable';

interface HostCapabilityState {
  readonly id: string;
  readonly support: 'supported' | 'partial' | 'unavailable';
  readonly owner: HostCapabilityOwner;
  readonly reason?: string;
}

interface ManagedRunDriver {
  start(input: {
    sessionId: string;
    projectRoot: string;
    surface: 'code' | 'partner';
    prompt: string;
    options: KodaXOptions;
    signal: AbortSignal;
  }): Promise<{ runId?: string; result: KodaXResult }>;
  abort(sessionId: string): Promise<void>;
}

interface RuntimeHostAdapter {
  initialize(): Promise<void>;
  capabilities(): readonly HostCapabilityState[];
  ensureSession(input: SpaceSessionIdentity): Promise<void>;
  readonly sessions: SpaceSessionPort;
  readonly runs: ManagedRunDriver;
  readonly workflows: SpaceWorkflowPort;
  close(): Promise<void>;
}
```

Rules:

1. The adapter returns Space-owned DTOs, never raw Runtime objects, callbacks, paths, or errors to renderer code.
2. `ensureSession()` may load or create an empty Runtime session, but must never overwrite an existing transcript.
3. A session selects its run driver before the turn starts. There is no mid-turn automatic fallback because that could execute tools twice.
4. The legacy driver and Runtime driver share the same option/event builder; they do not duplicate Partner or permission logic.
5. Runtime subscriptions are closed before Runtime shutdown and are not stored in renderer state.

## 6. Implementation sequence

Every work package follows RED -> GREEN -> REFACTOR. Production routing does not change until the preceding gate passes.

### P0 - Contract spikes and frozen fixtures

Goal: prove assumptions against the exact published package before structural refactoring.

- Add isolated probes for inline session create/load/list/transcript and settings.
- Add an inline mock-provider managed run with the existing callback shape.
- Verify `runtime.runs.start({ mode: 'managed_task', permissionBroker: 'client' })` preserves Space's callback authority.
- Verify Runtime returns one terminal result even when SDK callbacks include `onError` and `onComplete`.
- Record the resolved sessions, config, Runtime event, and run-status paths for all supported environment modes.
- Freeze representative Coder and Partner option/event fixtures from the current legacy driver.

Exit gate P0:

- no probe writes outside its generated test root;
- all required function-valued options work in inline mode;
- path behavior is documented and accepted;
- any failed contract becomes an explicit `space-bridge` or `unavailable` row before implementation continues.

Estimated size: 1-2 engineering days.

### P1 - Adapter skeleton and lifecycle

Goal: introduce composition without changing live behavior.

- Add `RuntimeOwner`, capability snapshot, and `RuntimeHostAdapter` with the legacy run driver selected.
- Initialize the adapter once after Space data-root environment setup.
- Add idempotent `close()` and include it in the existing 2.5-second shutdown watchdog.
- Add an internal process-start selector:
  - `KODAX_SPACE_RUNTIME_HOST=legacy`
  - `KODAX_SPACE_RUNTIME_HOST=runtime`
- Default remains `legacy` in this package until P4 acceptance is green.
- Add one `space.version` capability row describing the selected host, Runtime identity, and degradation without exposing local paths.

Exit gate P1:

- existing tests and packaged smoke are unchanged under `legacy`;
- initialization failure is visible and leaves a deterministic legacy route;
- no Runtime instance or subscription leaks after shutdown.

Estimated size: 1-2 engineering days.

### P2 - Session read path and first-run ensure

Goal: make Runtime the read substrate without dual mutation.

- Implement `ensureSession()` using load-first/create-if-missing semantics.
- Move list/load/transcript reads behind `SpaceSessionPort`.
- Preserve current filtering for ephemeral tags, ACP placeholders, surfaces, cursor pagination, title overrides, and in-flight precedence.
- Keep `KodaXHost` in-flight state and Space-only settings sidecar.
- Compare Runtime and legacy reads in tests only; production calls exactly one route.

Exit gate P2:

- the same fixtures produce equivalent visible session lists and transcripts;
- Partner sessions remain Partner after restart;
- Quick Ask ephemeral sessions remain hidden until promotion;
- no empty session is persisted before current product semantics require it.

Estimated size: 2-3 engineering days.

### P3 - Session mutations

Goal: move supported durable mutations to Runtime one by one.

Order:

1. append notice;
2. compact;
3. fork;
4. rewind;
5. archive/unarchive if exposed;
6. delete.

For each operation:

- write a parity test first;
- switch one production route;
- keep Space orchestration around cancellation, title, queues, local notices, artifact/workflow cleanup, and in-flight registry;
- remove or quarantine only the replaced SDK wrapper after the full suite is green.

Exit gate P3:

- an active run cannot be rewound or deleted;
- failed mutation leaves the prior session usable;
- fork lineage, titles, surface, project root, and runtime sidecar remain correct;
- delete does not orphan queues, permissions, artifacts, workflow origins, or title records.

Estimated size: 2-4 engineering days.

### P4 - Managed run driver

Goal: route new live turns through Runtime while reusing the existing Space bindings.

- Extract the direct call boundary from `RealKodaXSession` into `ManagedRunDriver`.
- Keep one shared construction path for KodaX options and events.
- Runtime driver:
  - ensures the session;
  - starts `mode: 'managed_task'` with `permissionBroker: 'client'`;
  - supplies the existing `KodaXOptions` and callbacks;
  - stores `runId` for cancel/dispose;
  - normalizes `RuntimeRunResult` into the current Space terminal semantics.
- Keep Space's queue as the only queue. Never call `runtime.runs.start()` for an already-running Space session.
- On cancel, abort Runtime and the existing signal, cancel brokers, drain the Space queue, and emit one Space cancellation terminal.
- Enable `runtime` by default only after all automated and human parity gates pass.

Exit gate P4:

- Coder and Partner option snapshots match legacy;
- exactly one completion/error/cancel terminal is emitted per turn;
- no duplicated tool execution, transcript entry, workflow event, or prompt queue entry;
- permission and AskUser display at most one modal and preserve deny/timeout behavior;
- Partner tool visibility, profile, delivery attribution, and verifier contract remain intact;
- stopping a run stops token/tool activity and does not leave a pending Runtime run.

Estimated size: 3-5 engineering days.

### P5 - Workflow and delegated capabilities

Goal: complete the adapter ownership map without creating parallel stores.

- Keep Workflow lifecycle and reads on the Space controller: review confirmed the raw Runtime manager does not preserve the controller's immediate stop projection, reason, durable restart merge, origin attribution, display metadata, and result/artifact bridges.
- Keep Workflow library, generated workflow editing, rename/delete/prune, origins, results, and artifacts in Space.
- Keep MCP and External Agent operations delegated to their current Space owners.
- Expose capability ownership as `runtime`, `space-bridge`, or `unavailable`; do not label a bridge as native Runtime support.
- Add contract tests ensuring the shared Runtime does not create a second MCP manager or External Agent plane.

Exit gate P5:

- Workflow state/actions are identical before and after routing;
- External Agent registrations/tasks survive restart in the existing Space store;
- one MCP server configuration produces at most one owned stdio process;
- capability diagnostics explain every delegated or unavailable action.

Estimated size: 2-3 engineering days.

### P6 - Default switch, stabilization, and documentation

Goal: make Runtime the default for the release while retaining a bounded rollback.

- Run the full verification matrix under both selectors.
- Change packaged/default selection to `runtime` only when Runtime gates are green.
- Keep `legacy` as an internal process-start rollback for the `v0.1.31` release only.
- Update HLD, capability ledger, user-visible diagnostics, changelog, and release checklist with actual—not planned—ownership.
- Do not delete the legacy driver in `v0.1.31`.

Exit gate P6:

- packaged smoke uses exact `0.7.68` with no sibling link;
- upgrade and restart preserve sessions and settings;
- rollback requires restart and does not rewrite/delete user data;
- no automatic mid-run fallback exists;
- all release documentation matches observed behavior.

Estimated size: 2-3 engineering days plus 3-5 days stabilization.

## 8. Rollout and failure policy

### 8.1 Selector policy

- The selector is internal and read once at process startup.
- It is not stored in user settings and is not a permanent product preference.
- Unknown values fail closed to the packaged default and emit a diagnostic.
- A live session never changes drivers.

### 8.2 Failure policy

- Initialization failure may select legacy before any Runtime operation starts.
- Read-only diagnostics may report partial/unavailable state.
- Once a mutation or managed run begins on Runtime, failure is returned to the user; Space must not replay it automatically on legacy.
- Rollback happens only after restart, avoiding duplicate network calls and tool side effects.
- No rollback path deletes Runtime event journals, Space sidecars, sessions, artifacts, or External Agent tasks.

### 8.3 Legacy removal gate

Legacy removal is a later reviewed cleanup, not part of `v0.1.31`. It requires:

- one stable released version with Runtime default;
- no unresolved severity-high parity issue;
- packaged upgrade/rollback evidence on Windows, macOS, and Linux;
- explicit confirmation that Space-only bridges no longer call the legacy run/session APIs being removed.

## 9. Risks and mitigations

| Risk                                                                | Mitigation                                                                                                              |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| A prompt/tool executes twice after Runtime failure.                 | Never auto-fallback after start; one driver per live turn; assert unique run/tool IDs.                                  |
| Runtime and SDK wrapper both mutate one session.                    | One route table per operation; production tests spy on the non-selected route.                                          |
| Duplicate renderer events from Runtime bus plus existing callbacks. | Runtime bus is journal/diagnostics only in this version; existing callback translator is the only renderer publisher.   |
| Permission waits race two brokers.                                  | Keep Space callback authoritative, use client-broker mode, and test a single modal plus Runtime phase/event settlement. |
| Runtime internal queue conflicts with Space queue.                  | Start Runtime only from an idle Space session; assert Runtime has no queued record in Space queue tests.                |
| Partner loses tool/profile/verification constraints.                | Reuse the exact options builder; snapshot effective config and tool exposure for Coder/Partner.                         |
| Custom profile/tests touch the real user home.                      | Resolve and assert all paths before Runtime creation; tests use unique onboarding roots.                                |
| External Agent data splits across two stores.                       | Do not install Runtime external-agent factories in the shared host; delegate to the existing gateway.                   |
| Two MCP managers spawn duplicate servers.                           | Do not call Runtime MCP tool reload/process paths; keep one Space manager owner.                                        |
| Shutdown exceeds the Electron watchdog.                             | Close subscriptions first, abort runs, close Runtime once, and measure shutdown in tests.                               |

## 10. Resolved implementation decisions

1. `<profile-root>/.kodax/runtime` is accepted as the KodaX `0.7.68` Runtime journal location. `KODAX_HOME`, `KODAX_PROFILE_DIR`, and onboarding isolation are covered by tests.
2. `space.version` exposes one summarized, redacted Runtime host capability row. Detailed health and action UI remains F090.
3. `KODAX_SPACE_RUNTIME_HOST=legacy|runtime` is sufficient for the bounded internal rollback window; there is no user-facing preference.
4. Space-only session fields remain in the existing sidecar until the Runtime contract has identical semantics.
5. External Agent durable ownership remains in `ExternalAgentGateway`; the shared Runtime does not install a second executor plane.
6. Space MCP management remains authoritative; the shared Runtime does not reload or start a second MCP process manager.
7. Production uses Runtime by default. Initialization failure can select legacy only before a run starts; a started Runtime operation is never replayed.

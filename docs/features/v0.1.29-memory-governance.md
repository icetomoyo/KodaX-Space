# v0.1.29 Addendum - F088 Memory Governance Surface

> Status: Completed
> Released: `v0.1.29`
> SDK baseline: KodaX F228 / `@kodax-ai/kodax@0.7.62`
> Purpose: preserve the completed F088 design record after the unreleased `v0.1.39` roadmap document was reassigned to F117.

## Delivered outcome

Space added a Coder-only Memory Governance popout that is explicitly separate from Partner KB and AGENTS.md editing. It consumes the public KodaX Memory Control Plane rather than creating a Space memory database.

Delivered views/actions:

- pending memory proposal inbox;
- bounded proposal preview and expected fingerprints;
- approve/reject with result-based blocked handling;
- active/trusted memory refs and readable snapshots;
- non-mutating curator reports;
- deterministic task-hint/MemoryPack diagnostics;
- source/session/artifact provenance where exposed;
- `/memory` commands and desktop entry points;
- Coder Memory versus Partner KB boundary labels.

## Public contract used

- `createMemoryControlPlane(...)`
- `listInbox()` / `showProposal(id)`
- `approveProposal(id, expectedFingerprints)` / `rejectProposal(id, reason?)`
- `listRefs(filter?)` / `readRef(ref)`
- `runCurator(input?)`
- `buildMemoryPack(input)`

Space passes session/project context from its trusted host and keeps file mutation inside the SDK approval action. The renderer never sends arbitrary paths to mutate.

## Important semantics

- Approval failure is result-based (`applied:false`) and remains visible as blocked.
- Fingerprints prevent stale preview/apply and changed `MEMORY.md` writes.
- `discoverSkills:false` keeps the surface focused on Coder Memory.
- Curator results are structural/deterministic unless a supported reviewer is supplied.
- Partner KB pages are never mixed into Memory refs.
- Unsupported edit/merge/archive/quarantine actions are not synthesized by Space.

## Relationship to F117

F117 does not reopen F088. It adds a desktop host for future KodaX KX-F260 Memory Agent lifecycle, outcome evidence, recall/change notices, scope, correction, rewind, and purge semantics while F228/F088 remain the durable governance foundation.

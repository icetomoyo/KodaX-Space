# v0.1.39 - Memory Agent Desktop Host

> Status: Planned / SDK-gated
> Feature: F117
> Hard gate: published KodaX KX-F260 capability and compatibility probe
> Existing foundation: F088 Memory Governance shipped in `v0.1.29` over KodaX F228

## Batch decision

Space will extend, not replace, the existing Coder Memory Governance surface. KodaX F228 remains the durable governance truth. KX-F260 adds a runtime Memory Agent that observes bounded evidence, recalls only already-ready relevant memory, records outcome digests, and promotes durable changes through F228 governance.

This version number is a capability slot. If KX-F260 is not published and compatible, F117 moves; the gate is not waived.

## FEATURE_117: Memory Agent Desktop Host

### User outcome

- Users can tell when durable memory changed and why, without seeing noisy internal recall narration.
- They can inspect scope, provenance, outcome evidence, applicability, conflicts, corrections, forget/purge results, and residual-source limitations.
- They can distinguish Coder Memory, Partner KB, Skills, and learned Extensions.
- Memory activity never blocks ordinary foreground work with repeated approval popups.

### Current evidence and gap

F088 already supplies:

- proposal inbox and fingerprint-guarded approve/reject;
- active/trusted memory refs and snapshots;
- curator reports;
- deterministic task-hint diagnostics;
- a Coder-only boundary separate from Partner KB.

KX-F260 is expected to add:

- `MemoryAgent` / `MemorySession` lifecycle;
- bounded observations and outcome digests;
- non-blocking ready-memory recall;
- rewind/complete/close semantics;
- applicability and identity scope;
- collapsed client notices;
- governed promotion through F228.

No implementation may begin from the design document alone. Space must verify the released export, DTO/event shape, capability negotiation, inline/Worker/daemon ownership, and failure semantics.

### UX

Extend the existing Memory popout with:

- **Overview**: enabled state, owner/runtime form, last meaningful memory change, pending decisions, warnings.
- **Inbox**: existing F228 proposals and preview/fingerprint behavior.
- **Memory**: active/trusted refs, applicability scope, provenance, readable bounded snapshot.
- **Episodes**: outcome digest records exposed by the public contract; no hidden chain-of-thought.
- **Activity**: collapsed durable-change, correction, conflict, forget/purge, and residual-source notices.
- **Governance**: curator, reject/correct/forget/purge operations only when supported.
- **Diagnostics**: task hint/recall trace metadata for advanced inspection, off by default.

Recall that merely influences a turn stays quiet unless KodaX exposes a safe attributable annotation. Space must not create a per-turn “memory thought” feed.

### Data and ownership

- Runtime owner runs Memory Agent work.
- F228 controller/store owns durable memory refs, proposals, fingerprints, and governance actions.
- Space owns only UI state such as selected tab and bounded cached query results.
- Partner KB remains project knowledge with source citations; it is never merged into Coder Memory lists.
- Learning Center may reference memory opportunities later, but F117 does not create a second learned-capability store.

### Security and privacy

- No direct LLM or renderer memory-file writes.
- Every durable mutation uses the public governance action and current fingerprint.
- Scope/identity is host-derived; project/user/agent/tenant applicability is never accepted from model tool input.
- Sensitive/private refs stay excluded unless the user explicitly enables a supported view.
- Forget/purge accurately reports residual source carriers it does not own.
- Memory notices contain bounded metadata, not raw private source bodies.

### Compatibility and failure

- F260 absent: retain the completed F088 experience with an honest unavailable explanation.
- Background review timeout: foreground result remains usable; pending digest/proposal remains discoverable according to SDK semantics.
- Owner restart: rebuild state from Runtime/F228; do not replay jobs in the renderer.
- Rewind: follow SDK sequence semantics and show what was invalidated.
- Unsupported correction/purge action: hide or disable with an explicit capability reason.

### Explicit non-goals

- No second memory database, vector store, embedding service, graph store, or transcript copy.
- No always-running advisor conversation.
- No raw chain-of-thought or per-turn memory narration.
- No direct Partner KB/Skill/Extension mixing.
- No Space-owned memory promotion heuristic.
- No claim that every failure is reusable knowledge.

### Automated acceptance

- Compatibility probe verifies the exact F260 public surface and capability flag.
- Existing F088 fingerprint/stale/reject/curator/pack tests remain green.
- Scope leakage, rewind, owner restart, timeout, notice dedupe, correction, and purge semantics have deterministic tests.
- Inline/Worker/daemon behavior is tested only for forms the published contract supports.
- F260-disabled behavior is equivalent to the F088 baseline.

### Human acceptance

- Complete a task that yields a governed durable memory change and inspect the collapsed notice/provenance.
- Reject/correct/forget a supported item and verify the next session reflects the result.
- Resume a session and verify no duplicate episode or notice.
- Confirm Partner KB content never appears as Coder Memory.

### Rollout and rollback

- Ship behind Runtime capability negotiation and a Space policy flag during the first release.
- Rollback disables Memory Agent activation while leaving F228 governance and existing durable memory readable.
- Never delete memory data as part of rollback.

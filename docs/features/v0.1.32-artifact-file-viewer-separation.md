# F131 - Artifact and File Viewer Separation

> Target: `v0.1.32`
> Status: InProgress
> Category: Enhancement / Refactor
> Priority: High
> Started: 2026-07-20
> SDK gate: None; this is a Space-owned renderer and IPC boundary.

## User problem

Opening a project folder and previewing a file before the first Session currently routes the file through the Artifact workspace. The renderer creates a project-derived pseudo Session ID, refreshes the Artifact list, and layers the transient file preview over that result. If the unrelated Artifact refresh fails, the sidebar shows `Artifact (!)` and `Artifact refresh failed` above a file that rendered successfully.

This combines two different user objects:

- an **Artifact** is a Session-owned generated result with durable identity, provenance, versions, export, and iteration actions;
- a **project file** is a project-owned read-only document opened temporarily for inspection and does not require a Session.

The shared rendering capability is useful, but the shared state, navigation, refresh, and error semantics are not.

## Decision

Split the right-sidebar capability model into three explicit modes:

```text
Overview        task/session facts
Artifacts       Session-scoped generated results
File Viewer     project-scoped or Delivery-backed read-only file
```

Artifact and File Viewer continue to reuse the existing safe preview stack for Markdown, code, HTML, SVG, PDF, Office, images, video, and audio. They do not reuse list ownership, selection, versioning, actions, or failure state.

### State matrix

| State                     | Visible modes                        | Required reads                                        | Error ownership          |
| ------------------------- | ------------------------------------ | ----------------------------------------------------- | ------------------------ |
| No Session, no open file  | Overview                             | None                                                  | None                     |
| No Session, file open     | Overview + File                      | File preview only                                     | File Viewer              |
| Session, no Artifact      | Overview; File when open             | Real Session Artifact list                            | Artifact empty state     |
| Session with Artifacts    | Overview + Artifacts; File when open | Real Session Artifact list plus optional file preview | Each mode owns its error |
| Artifact refresh failure  | Overview + Artifacts `(!)`           | Real Session Artifact list                            | Artifacts only           |
| File read/refresh failure | Overview + File                      | File preview only                                     | File Viewer only         |

### Navigation behavior

- Opening a workspace file or Partner Delivery activates `File` and opens the right sidebar at its balanced width.
- Focusing an Agent-created result activates `Artifacts` and preserves its selected Artifact/version behavior.
- The File tab exists only while a file preview is held. Closing or changing the project clears it.
- A File preview survives creation or switching of a Session within the same project because it is project-scoped.
- Artifact selection is cleared on Session change and never leaks across Sessions.
- When both capabilities are present, the order is `Overview | Artifacts (n) | File`.

## Capability and data boundaries

### Artifacts

- Requires a real `currentSessionId` for list and create/version events.
- Uses `artifact.list`, `artifact.read`, `artifact.readBinary`, `artifact.export`, and Artifact change pushes.
- Owns generated-result empty/loading/error states, version selection, iterate, save/export, and standalone Artifact windows.
- `Artifact (!)` is valid only when a real Session Artifact read fails.

### File Viewer

- Requires only an allowed project root and a project-relative path, or a resolved Partner Delivery reference.
- Uses a transient `source: file-preview | delivery-preview` snapshot and never inserts it into the Artifact list.
- Owns file title/path, reread, copy-path feedback, file-specific loading, and file-specific failure text.
- Does not expose Artifact version, iterate, Artifact selector, Artifact count, or Artifact refresh state.

### Shared preview layer

The existing `ArtifactView`/`RichPreview` renderer stack remains the common presentation layer. The new File Viewer adapts a transient file snapshot into that pure rendering input without constructing a durable Artifact or querying the Artifact store.

The existing `artifact.previewFile` endpoint remains a legacy, Session-scoped Artifact compatibility contract. File Viewer does not call it. Content-backed files use the existing project-scoped `files.read` channel, while the shared rich-preview stack uses `files.stat` and `files.readBinary` for path-backed formats. This keeps File Viewer compatible with an already-running main/preload process during renderer hot reload and preserves the existing project allowlist, path-boundary, and binary-size guards.

## Event model

- `kodax-space.focus-artifact`: durable or transcript-backed generated Artifact focus only.
- `kodax-space.open-file-viewer`: workspace-file and Delivery-file focus only.

The Shell opens the right sidebar for either event. Coder and Partner right-sidebars consume the file event independently from Artifact focus. A compatibility guard routes any legacy file-preview snapshot received on the Artifact event into File Viewer rather than recreating the mixed state.

## Failure semantics and accessibility

- No Session is an absent capability, not an error.
- Artifact failures never appear inside File Viewer.
- File refresh failures keep the last successfully rendered content visible and show a file-specific message.
- Tabs use semantic buttons with `aria-pressed`; the active mode is not communicated by color alone.
- Error text names the failed object and operation. Destructive-red styling is reserved for a real failure, not an unavailable capability.
- Refresh and copy controls retain visible tooltips/accessible labels and existing keyboard focus behavior.

## Scope

### Included

1. Renderer state and event separation for Coder and Partner right-sidebars.
2. Removal of project-derived pseudo Session IDs from Artifact list queries and removal of Artifact IPC from file-preview requests.
3. A dedicated File Viewer component using the shared safe preview renderers.
4. File-specific localization, refresh, copy-path, empty/error semantics, and stable project/session transitions.
5. Schema, unit, Electron E2E, typecheck, lint, and production renderer/main smoke verification.

### Not included

- Editing files in the viewer.
- Multiple persistent file tabs, recent-file history, pinning, or restoring an open file after app restart.
- Promoting a project file into an Artifact.
- Changing Artifact storage, version retention, export, or sandbox policy.
- Redesigning the Files explorer, Changes, Context, or Partner Results information architecture.
- Renaming or removing the legacy Artifact compatibility IPC channel during `v0.1.32`.

## Implementation plan

### P1 - Contracts and regression tests

- Route project file reads through existing project-scoped `files.*` contracts and preserve the legacy Session-scoped `artifact.previewFile` schema.
- Add a typed File Viewer event and source predicate.
- Add tests proving file-preview and Delivery-preview snapshots are File Viewer inputs while generated snapshots remain Artifacts.
- Extend Electron E2E to prove a new project with no Session shows `Overview | File`, has no Artifact tab/error, and renders the file.

### P2 - Shared rendering adapter

- Add `FileViewer` with a file header, refresh, copy-path feedback, and the existing safe preview body.
- Keep the last successful snapshot visible if refresh fails.
- Do not expose Artifact-only controls.

### P3 - Coder sidebar state split

- Query Artifacts only with the real `currentSessionId`.
- Add the dynamic File tab and separate focused file state.
- Keep File state across Session changes within the project; clear it on project change.
- Preserve current Overview and Artifact behavior for real generated results.

### P4 - Partner parity and caller migration

- Add the same transient File mode to the Partner Artifact/Outputs rail.
- Route Files, Context, file menus, Markdown links, and Partner Delivery preview actions through File Viewer naming and events.
- Preserve smart diff routing for changed code files and system reveal fallback for unsupported files.

### P5 - Verification and release evidence

- Run schema and renderer-model tests first, then the focused desktop suite.
- Run the no-Session File Viewer Electron E2E plus existing rich-preview coverage.
- Run typecheck, targeted lint/format checks, and the production renderer/main smoke build.
- Produce the F131 human test guide and update Feature List status/evidence.

## Acceptance criteria

- Opening a previewable project file with no Session shows `Overview | File`; `Artifacts`, `Artifact (!)`, and `Artifact refresh failed` are absent.
- No `artifact.list` request is made with a project-derived or synthetic Session ID.
- File preview requires only a project; creating a Session is not a prerequisite.
- A real Session Artifact still auto-opens Artifacts, lists versions, exports, iterates, and follows `artifact.changed`.
- With both a real Artifact and an open file, the user can switch among Overview, Artifacts, and File without losing either selection.
- Session changes clear Artifact focus but preserve the project File Viewer; project changes clear the File Viewer.
- Workspace and Partner Delivery files use File Viewer in both Coder and Partner surfaces.
- Artifact and File Viewer failures remain isolated and name the correct object.
- Existing sandbox, path-boundary, Office ZIP guard, preview-size, and Delivery ownership rules remain unchanged.

## Rollback

The change is renderer-local and reuses existing `files.*` IPC contracts. Rollback restores the prior event routing and combined panel without migrating or deleting stored data. Artifact storage, IPC schema compatibility, and project files are unchanged.

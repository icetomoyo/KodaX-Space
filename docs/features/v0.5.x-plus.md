# KodaX Space Post-v0.5.x Security Hardening

> Status: Planned, not before completion of the `v0.5.x` product line
> Product owner: KodaX Space
> SDK gate: None; this is a Space-owned native execution and packaging boundary

## FEATURE_138: OS-Enforced Document and Native Tool Sandbox Hardening

### 1. 需求概述

F137/F129 先通过有界 Worker、独立子进程、私有 staging、超时取消、进程树清理、禁宏和
输入结构限制完成功能闭环。F138 在产品功能成熟后，为 PDF/OOXML 解析、Office
render/recalculation、OCR 和其他受控 native adapter 增加真正的 OS 强制隔离。

F138 不回溯阻塞 `v0.1.34` 或 `v0.1.67`，也不改变 Skill、Document Job、Presentation
Project 或 Delivery 的用户工作流。它替换执行 backend，把当前明确披露的 residual risk
收敛为可测试的平台安全能力。

### 2. 影响范围

- 新增统一 `NativeToolSandboxBackend`，供 Document Job、Presentation Worker 和后续经审查
  的 native adapter 复用。
- Windows、macOS、Linux 分别提供 release-qualified backend 和 capability probe。
- 扩展安装包签名/notarization、native helper SBOM、平台兼容矩阵、诊断和回滚。
- 复用现有 staged input/output、F098 policy/audit、F114 delivery/checkpoint 和 job
  cancellation；不修改 KodaX SDK，不把沙箱放进 Runtime。
- 不把 worktree、Worker thread、Electron renderer sandbox 或普通 child process 冒充 OS
  安全沙箱。

### 3. 技术方案

#### 3.1 共同约束

- 输入只读映射到单次 job，输出只允许写入新的私有 staging root；所有 canonical path、
  symlink/junction/reparse point 和 archive traversal 在进入 backend 前后复核。
- 默认无网络 capability，不继承主进程凭据、token、代理、用户 profile 或任意环境变量。
- 只允许运行锁定版本的 adapter/renderer 及其必要子进程；禁止 shell 和任意进程启动。
- 对整个进程树施加 CPU、RSS/native memory、进程数、句柄/文件数、wall-clock、读写字节和
  输出大小限制；取消、超时或宿主退出时整树终止。
- 每个平台明确报告 `unsupported`、`audit-only` 或 `enforced`，绝不把 best-effort 设置
  显示为 OS 强制隔离。

#### 3.2 平台 backend 候选

- Windows：Job Object 管理整树与资源；AppContainer 或等价受限 token/完整性级别限制文件、
  注册表、凭据和网络；仅向 job staging ACL 授权。
- macOS：签名并 sandboxed 的 XPC/native helper，使用 App Sandbox entitlement 和独立
  container/profile；通过 notarization 和 hardened runtime 门禁。
- Linux：优先使用无 root 的 user/mount/network namespace、seccomp、cgroup/rlimit 组合；
  可选 `bubblewrap` 只能通过受审计、可探测、可打包/部署的策略接入。

最终技术选择由实现期 threat model、平台可用性和发布证明决定，本设计不把候选工具名称
提前写成已交付事实。

#### 3.3 迁移策略

1. `off`：保持 F137/F129 已发布的基础执行路径。
2. `audit-only`：同一 fixture 在 sandbox backend 中运行并比较产物、性能和失败语义，不影响
   用户主路径。
3. `enforced`：单个平台的功能、保真、性能、签名和攻击 fixture 全部通过后，该平台的目标
   adapter 切换到 OS backend。
4. 回滚只切换 backend，不改写现有项目、job manifest、产物或 validation receipt。

### 4. 接口契约

```ts
type NativeSandboxState = 'unsupported' | 'audit-only' | 'enforced';

interface NativeSandboxCapabilities {
  readonly platform: 'win32' | 'darwin' | 'linux';
  readonly state: NativeSandboxState;
  readonly filesystemIsolation: boolean;
  readonly networkIsolation: boolean;
  readonly processIsolation: boolean;
  readonly nativeResourceLimits: boolean;
  readonly backendVersion?: string;
}

interface NativeSandboxJob {
  readonly jobId: string;
  readonly executableId: string;
  readonly inputStageIds: readonly string[];
  readonly outputStageId: string;
  readonly deadlineAt: string;
  readonly policyRevision: string;
}
```

- 调用方只能提供受信 catalog 中的 `executableId` 和 staged IDs，不能提供任意 executable、
  argv 路径、环境变量或 host path。
- receipt 记录实际 backend/state/policy revision、资源终止原因和未强制的维度。
- `enforced` 标签必须来自 backend 的运行时证明和 release matrix，不能由配置开关伪造。

### 5. 实现步骤

1. 为 Document/Presentation/native adapter 建立共同 threat model 和攻击面清单。
2. 冻结 backend 协议、能力状态、策略版本、诊断和回滚接口。
3. 先实现 Windows release backend，再根据正式发行优先级实现 macOS/Linux。
4. 建立正常/超时/崩溃、文件越界、网络尝试、子进程逃逸、native-memory exhaustion、
   句柄耗尽、孤儿进程和签名破坏 fixture。
5. 以 `audit-only` 对照现有 F137/F129 产物、性能、字体、Office/OCR 行为和错误语义。
6. 单平台通过全部门禁后逐 adapter 切换 `enforced`，保留可审计回滚。
7. 更新安装器、SBOM、签名/notarization、诊断包、用户风险说明和人测手册。

### 6. 验收标准

- OS backend 不改变 F137/F129 的功能、产物 hash 语义、Delivery、checkpoint、取消和恢复
  契约。
- 文件读取仅限 staged inputs，写入仅限 staging output；host profile、凭据和其他项目不可见。
- 无网络 capability 的 job 无法建立外连；未允许子进程不能逃离同一资源/终止边界。
- CPU、native memory、进程、句柄、文件、时间和输出预算在 OS 层可重复触发并产生结构化
  receipt。
- timeout/cancel/crash/Space 退出均无残留进程和明文临时文件。
- `unsupported`/`audit-only` 平台不显示 `enforced`；每个正式支持平台都有签名构建、
  packaged smoke、攻击 fixture 和回滚证据。
- F138 上线前后，缺少 OS backend 都不会回溯删除或损坏用户既有 Document Job、
  Presentation Project 和交付物。

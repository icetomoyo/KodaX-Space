# v0.1.41 - Partner Knowledge Integrity

> Status: Planned

> Position: local knowledge-integrity release after F125/F126; `v0.1.42` is the dedicated stabilization reserve

## Batch decision

This release makes local project knowledge trustworthy under change. It covers source updates, missing files, conflicts, stale accepted knowledge, access-state changes, retention, export, and deletion using the F122 source/version contract.

Production connector authorization and revocation remain owned by F096 in `v0.2.3`. F127 defines and tests the fail-closed source-state adapter that F096 must satisfy before connector content can participate in Partner retrieval.

## FEATURE_127: Knowledge Freshness, Conflict, and Access Integrity

### User outcome

When a local source changes, disappears, conflicts with another source, or becomes unavailable, Partner identifies affected knowledge and answers conservatively. Users receive an actionable review item instead of silently continuing with stale or unsupported claims.

### Dependency and impact model

- Maintain bounded links from source version/locator to knowledge claim/page version and from superseded page to replacement.
- A new source version computes changed/removed evidence units and marks dependent active knowledge for review without rewriting it.
- Impact records include cause, affected claims/pages, old/new versions, severity, detected time, and proposed action.
- Refresh remains immutable: old citations stay attached to old source versions.

This dependency model supports provenance and maintenance. It is not F075 semantic knowledge-graph retrieval.

### Freshness and conflict behavior

- Freshness uses source/content version, parser/index generation, availability state, and explicit review time rather than page `updatedAt` alone.
- Conflict detection proposes a review group when two permitted sources or active pages make incompatible claims within the same subject/time scope.
- Partner answers cite both sides, distinguish dates/authority, label uncertainty, and avoid silently choosing a winner.
- Users resolve by accepting a replacement decision, recording scope/time differences, or keeping an explicit unresolved conflict.
- New evidence can reopen a resolved conflict with a new audit event.

### Access-state contract

- Any source adapter exposes permitted, unavailable, or revoked/restricted state plus a non-secret reason code.
- Unavailable/restricted sources are immediately excluded from new lexical, vector, cache, full-context, preview, and answer paths.
- Derived knowledge moves to `restricted` when continued use would expose evidence no longer permitted by its provenance/retention policy.
- Unauthorized UI and diagnostics cannot reveal source titles, excerpts, account identity, or inferred sensitive claims.
- Reauthorization never assumes that a new identity/account is equivalent to the previous one.

Local missing/removal and project access changes ship here. F096 must map connector revocation, account switching, and snapshot provenance into the same contract before enabling connector-backed retrieval.

### Retention, export, and deletion

- Users can inspect retained source versions, chunks/vectors, citations, knowledge versions, traces, and audit records.
- Delete/forget previews downstream impact, removes eligible canonical content, and rebuilds/removes derived indexes and caches.
- Retention exceptions are explicit and never presented as deletion success.
- Project export preserves portable source manifests, accepted knowledge, versions, citations, conflicts, and integrity hashes without credentials or inaccessible excerpts.

### Updates inbox

The Updates view groups changed/missing sources, failed jobs, stale knowledge, conflicts, restricted content, and proposed refreshes. Batch actions are bounded, previewed, and return per-item results.

### Acceptance

- Changed, renamed, deleted, missing, access-restricted, conflicting, partially supported, retained, exported, and deleted local-source scenarios have deterministic tests.
- Source refresh never rewrites an accepted page or redirects an old citation to different content.
- Restricted evidence cannot leak through FTS5, vectors, caches, full-context packs, answer traces, previews, exports, artifacts, or diagnostics.
- Impact propagation is idempotent and crash/restart safe without duplicate review items.
- Conflict resolution preserves original evidence and accepted resolution history.
- A deterministic mock connector proves the adapter contract; F096 remains responsible for production connector auth/revocation acceptance.

## Release acceptance

- Change a source supporting an active decision and receive a precise stale review item while the old version remains auditable.
- Ask a question covered by conflicting sources and receive a conflict-aware answer with both citations.
- Remove/restrict a source and prove it disappears from every retrieval route and cache.
- Export or delete a project knowledge set with a complete, redacted impact receipt.

## Rollout and rollback

- Gate impact propagation, automatic stale state, conflict detection, and Updates inbox independently.
- Access exclusion and revocation/restriction handling are fail-closed and cannot be disabled by a feature rollback.
- Rollback disables automatic maintenance actions while preserving readable permitted versions, citations, exports, and audit evidence.
- `v0.1.42` is reserved for freshness, conflict, deletion, retention, cache invalidation, and migration regressions.

# KodaX Space v0.1.41 — Provider Recovery and Latest KodaX Alignment

> Status: Released on 2026-08-14; final status and CI evidence are recorded in the [release-readiness record](../releases/v0.1.41-release-readiness.md).
> Date: 2026-08-14
> Scope: release metadata, documentation, manual synchronization, and the already-landed provider-recovery compatibility work.

## Release intent

v0.1.41 packages the provider-recovery reconciliation already present in the
working tree and aligns Space with the latest npm `@kodax-ai/kodax` release at
release preparation time. The npm registry reports `0.7.87` as `latest`; both
Space manifests and the lockfile pin that exact published package.

This is a compatibility, recovery, and release-documentation update. Release
preparation does not introduce a new system business rule or a new KodaX SDK
contract.

## KodaX dependency gate

The exact dependency is:

```text
@kodax-ai/kodax@0.7.87
sha512-FqVKGdVqkO0RX49e9+xbdN1bG8CwjBtVuInVgLdSS7hpBjAxUf5W5a/+y3pja2Jj6826pzp7v5VXj6RChyLYQQ==
```

The root and Desktop manifests, package-lock Registry URL, installed package,
provider capability data, and runtime compatibility checks must agree. A
future KodaX release is not accepted implicitly by a range; the release gate
must re-check npm `latest` and then use one exact version and SRI.

## Provider recovery reconciliation

KodaX already emits ordered `provider.recovery` events with Session/Run/Turn
identity and cursor provenance. Space consumes that existing event in the
daemon bridge and projection paths:

- live rendering removes only the provisional assistant/thinking attempt when
  the recovery action replaces that attempt;
- terminal history reconciliation preserves the recovery diagnostic at its
  causal boundary and shows only the replacement output;
- reconnect hydration, Session switching, active observation replay, and Ctrl+R
  converge on the same transcript;
- fresh retries, `manual_continue`, malformed/child recovery events, completed
  tool receipts, and legitimate repeated text retain their existing behavior;
- no content-based deduplication, new SDK event, field, capability, or Runtime
  projector is added.

## Provider defaults

The Zhipu Coding Plan catalog follows the installed KodaX 0.7.87 provider
capability data and keeps the `GLM-5.3` default and canonical effort mapping.
Space-owned catalog overrides remain presentation and disaster-recovery
metadata; SDK provider capability JSON remains the primary source of truth.

## Boundaries

- Coder remains Runtime-owned; Space remains the presentation, policy, review,
  history, and manual overlay host.
- Partner remains Space-owned embedded-inline.
- F117 Memory Agent Episodes/Activity/correction/forget/purge UX is not part of
  this release.
- F138 broad document/native-resource OS isolation is not claimed by the
  command sandbox facade.
- The final human multi-client acceptance ledger for F121 remains separately
  tracked.
- If a GitHub check requires a change, it must stay in tests, smoke probes, CI
  configuration, or release documentation. Business-logic changes require
  explicit review before proceeding.

# F134 — Canonical Context Compaction Experience

## User outcome

Manual and automatic compaction stay visibly active without freezing the composer, then leave one trustworthy result. The context gauge cannot jump back to a stale pre-compaction value, and the user can distinguish a committed reduction from a valid unchanged outcome.

## Ownership and event contract

- KodaX Runtime owns daemon-backed compaction policy, execution, context identity, revision, and canonical lifecycle events.
- Space owns immediate command echo, responsive progress presentation, validated IPC projection, root-context selection, and human-readable outcome copy.
- A daemon-backed manual request must not synthesize a second legacy lifecycle. Embedded/legacy sessions retain the Space-owned compatibility lifecycle until they adopt the Runtime contract.
- `context.compaction.finished` is projected for both committed and unchanged outcomes. Its source, elapsed time, strategy, effective trigger, protected budget, accounting components, and before/after revisions remain optional forward-compatible facts.
- Root usage accepts only a same-context revision that is not older than the current projection. Child context events never overwrite the root gauge.
- Space requires `contextCompaction: 3`, `transcriptPaging: 1`, and `transcriptSearch: 1`. Compaction v3 adds the durable-before-evict exact-history boundary; paging and search remain separate negotiated capabilities rather than being inferred from the KodaX version.
- The canonical producer checkpoint bytes, including recovery guidance, are reused by Session lineage so the compaction entry, first-kept pointer, and post-compact attachments remain on one active path. Legacy suffix-free checkpoints remain readable.
- Root and persistent child Agents recover only their own isolated history. Child compaction and live-only state remain observable through attributed diagnostics but cannot replace the root transcript/live projection.

## Presentation

- `/compact` appears immediately and the animated compacting state remains active until the authoritative end event.
- A committed outcome shows before, after, reduction, and optional source/duration.
- An unchanged outcome keeps the authoritative active-input value and says that no replacement was committed; it is not presented as a failure.
- The gauge labels current active model input separately from the latest compaction transition.
- From `v0.1.33`, the gauge and composition percentages use the final effective auto-compaction threshold, not the model's physical maximum context, as their denominator.
- Model maximum context and the current auto-compaction threshold are independent facts. The UI never explains an absolute threshold as though it were necessarily derived from the configured percentage.
- The latest-model-request composition always lists six rows: system prompt, tool schemas, combined Skills / MCP, messages, request input, and recent tool results, including zero-valued categories. "Request input" is the current-turn input sent in that snapshot, not an unprocessed queue; completed content moves into messages on a later request. Reserved response capacity is not active input and is not presented as auto-compaction headroom.
- Cumulative Session usage is a separate indicator. It sums Provider-reported root and child-Agent physical calls and therefore does not fall when the root context is compacted.

## Acceptance

- Runtime manual compaction emits one start/finished/end lifecycle to the renderer.
- A late lower revision cannot replace a newer post-compaction root token count.
- Committed and unchanged canonical outcomes validate through IPC and preserve supported KodaX metadata.
- Child compaction never changes the root gauge.
- Exact pre-compaction lineage is durable before the slim snapshot is published; revision-bound page/chunk/search reconstructs the available history without using the legacy unbounded transcript endpoint.
- Exact checkpoint/recovery-guidance bytes reconstruct without a duplicate synthetic sibling; post-compact attachments follow the compaction entry on the active lineage and legacy suffix-free fixtures still resume.
- Embedded/legacy manual compaction still receives a complete compatibility lifecycle.
- The effective-window progress bar exposes the resolved threshold as its semantic maximum, excludes reserved response capacity from the fallback input count, and does not display reserved-response/physical-headroom segments.
- Provider-reported root input remains authoritative when both the iteration count and a context-budget snapshot exist.
- The Session-usage surface counts each Provider call once, keeps child usage out of the root gauge, presents total input before Provider-reported uncached/cache-read/cache-creation subsets, and warns that tokenizer/cache field conventions differ across Providers.
- Focused projection/store/spinner tests, desktop type checks, and a production build pass.

## Implementation record

- Completed on 2026-07-21 against exact KodaX 0.7.74 contracts; refreshed on 2026-07-25 against the npm-published KodaX 0.7.76 package for the same compaction v3/search, exact checkpoint lineage, and imperative flat-history-to-lineage reconciliation.
- Runtime-backed manual compaction now has one canonical lifecycle; root UI projections ignore
  child contexts and stale revisions.
- Transcript restoration uses revision-bound page/chunk/search reconstruction, including entries
  larger than the daemon observation limit and exact compacted-history recovery where durable bytes exist.
- IPC schema build, 50 focused Space tests, exact Runtime compatibility, desktop typecheck, and the
  production smoke build pass.

  bounded category counts through the validated Session-event schema.

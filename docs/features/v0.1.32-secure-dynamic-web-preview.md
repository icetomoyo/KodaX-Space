# F133 - Secure Dynamic Web Preview

> Target: `v0.1.32`
> Status: Completed
> Category: Enhancement / Security
> Priority: High
> Started: 2026-07-21
> SDK gate: None; Space owns the Electron protocol, renderer sandbox, and File Viewer UI.

## Problem

Artifact and File Viewer correctly have separate ownership after F131, but their HTML
presentation still assumes a self-contained document. A project page that works in a browser
can render only its shell, lose styles, or expose inert controls in Space when it depends on
relative JavaScript/CSS/media, module imports, local fetches, storage, workers, or an external
API. The isolated frame currently gives no visible explanation when one of those requirements
is blocked.

## Decision

Keep the existing trust boundary instead of making all generated HTML browser-equivalent:

- Artifact `html` remains inert and script-disabled.
- Artifact `interactive-html` remains an opaque-origin, permission-declared single-document
  sandbox.
- A workspace HTML file opened in File Viewer receives a capability-scoped project preview
  origin. It may run inline and local scripts, load relative assets and modules, use same-origin
  storage/fetch/worker APIs, and submit local forms.
- File Viewer loads HTTPS presentation dependencies already authored in the document, such as
  stylesheets, fonts, images, media and script entry points, so security policy does not silently
  dismantle the page. Arbitrary fetch/WebSocket access remains disabled by default. A per-file
  network switch permits additional HTTPS/WSS requests for trusted pages without granting
  Electron, Node, IPC, popup, nested-frame, or top-navigation access.
- Both dynamic HTML paths report bounded runtime, resource, and policy diagnostics in the
  preview instead of failing as an unexplained blank page.

## Security contract

The project preview URL is an unguessable, in-memory capability rather than a filesystem path.
Its host identifies one canonical directory scope and one network mode. The protocol handler:

1. creates a capability only after project allow-list and canonical path checks;
2. scopes relative and root-relative requests to the selected HTML file's directory;
3. rejects path traversal, symlink escape, credentials, ports, unsupported methods, directory
   reads, sensitive dotfiles, and non-preview file types;
4. bounds the capability cache and expires idle entries;
5. emits explicit MIME, no-sniff, no-store/no-cache, CORS and preview-specific CSP headers;
6. never exposes a native project path in a URL or child document;
7. keeps the child on an origin distinct from `app://space` and prevents preload bridge
   exposure outside the trusted main frame.

The default CSP allows the capability origin, inline code required by authored pages, data/blob
media, local workers, and bounded HTTPS origins explicitly present as display dependencies in the
document. It does not grant arbitrary connection targets. The network-enabled CSP adds general
HTTPS/WSS resources and connections. Frames, objects and popup/top navigation remain unavailable
in both modes.

## UX

- File Viewer automatically uses dynamic project preview for workspace `.html`/`.htm` files.
- A compact toolbar control communicates `local/authored resources` versus `additional network
requests`, is keyboard reachable, and warns through its accessible label that expanded network
  mode is for trusted pages.
- Refresh re-reads the file and reloads the preview without changing Artifact state.
- Runtime errors, failed resources and policy violations appear as a compact, dismissible
  diagnostic. Raw messages are length-bounded before crossing into React state.
- Markdown, Office, media, code and Delivery-backed previews keep their existing behavior.

## Implementation plan

1. Add typed `files.webPreview` IPC and a pure, unit-tested capability registry/resolver.
2. Extend the `app:` protocol and CSP routing for capability hosts and a fixed diagnostics
   runtime.
3. Add a File Viewer project-web component and local/network toolbar state.
4. Add bounded diagnostics to project preview and interactive Artifact HTML.
5. Verify schema, path/symlink/method/expiry/CSP policy, renderer typing, lint, build, and
   focused Electron interaction.

## Acceptance criteria

- A project page can load relative JS, CSS, images, module imports, local fetches and workers.
- Inline buttons, timers and animations continue to work in interactive Artifacts.
- External requests fail closed by default and work only after the user enables network mode.
- A preview cannot read above its scoped directory, follow a symlink outside it, access hidden
  secrets, invoke Space IPC, open popups, embed frames, or navigate the top-level Space window.
- Missing files, script exceptions and CSP blocks produce visible diagnostics.
- No-Session File Viewer remains independent from Artifact list/refresh/error state.

## Delivery result

- Added the typed `files.webPreview` channel and a bounded in-memory capability registry with
  canonical project/path checks, directory scoping, expiry, LRU eviction, sensitive-file and
  extension policy, symlink-escape protection, and a 50 MB per-resource limit.
- Added a dedicated `app://preview-<capability>/` origin with explicit MIME/CSP/cache headers,
  local modules, fetch, storage and workers, authored HTTPS display dependencies, plus a per-file
  switch for additional secure-network requests.
- Kept genuinely static Artifact `html` inert and `interactive-html` opaque-origin, while promoting
  content that requires browser presentation dependencies and adding bounded diagnostics.
- Made Artifact classification inspect the complete bounded document, recover legacy static
  metadata at render time, and support authored HTTPS scripts, CSS imports, blob workers and
  ephemeral storage inside the opaque sandbox.
- Restricted the preload bridge to the trusted top-level Space renderer and confined child-frame
  navigation to the exact Artifact and project-preview endpoints.
- Verified schema and security policy with focused tests, Renderer/Electron type checks, targeted
  lint/format checks, production smoke build, and a Playwright interaction trace covering local
  CSS, modules, JSON fetch, storage, workers and button behavior.

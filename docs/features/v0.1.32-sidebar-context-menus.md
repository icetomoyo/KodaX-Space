# F132 - Codex-Aligned Sidebar Context Menus

> Target: `v0.1.32`
> Status: InProgress
> Started: 2026-07-20
> Category: Enhancement
> Priority: High
> SDK gate: None; Space-owned renderer behavior over existing safe project/session IPC

## User outcome

Project and task rows in the left sidebar expose compact, predictable menus that match the hierarchy, density, grouping, and placement of the supplied Codex references. Every enabled item performs a real action. Archive is not offered; removal/deletion remains the only destructive lifecycle action until archive receives a complete product design.

## Reference behavior

The supplied project-menu reference uses an icon-led compact menu anchored to the project row. The supplied task-menu reference uses text-only grouped actions anchored to the selected task. Both use a light elevated surface, generous radius, subtle border/shadow, full-row hover targets, and separators between action families.

Space keeps its existing theme tokens and Lucide icon system so the same hierarchy works in light and dark themes.

## Action inventory

### Project menu

1. Pin project - move the project to the top of the persisted manual project order.
2. Open in file manager - enter the project directory through the allowlisted, directory-only `shell.openDirectory` boundary.
3. Rename project - enter the existing inline rename flow.
4. Remove from Space - keep the existing confirmation and never modify the folder on disk.

### Task menu

1. Pin/unpin task.
2. Rename task.
3. Mark as unread/read.
4. Open the task project directory itself in the system file manager.
5. Copy working directory.
6. Copy conversation ID.
7. Continue in a new task - reuse the existing durable session fork route.
8. Delete task - keep the existing confirmation and running-session rejection behavior.

## Explicit exclusions

- No project or task archive action. Legacy archived projects remain readable/removable but no new archive transition is exposed.
- No permanent-worktree or continue-in-worktree action until Space owns a worktree create/select/cleanup contract.
- No deep-link copy action until the application registers and routes a stable session URL scheme.
- No open-in-new-window action until multi-window session observation, focus, and event fan-out are explicit.
- No disabled or inert placeholder rows for excluded capabilities.

## Interaction and accessibility

- Project and task menus share one portal-based surface, viewport clamping, outside-click dismissal, Escape dismissal, roles, and focusable full-row targets.
- Project actions use Lucide icons to match the supplied reference; task actions remain text-only to match the task reference.
- Destructive rows use the existing danger token. Clipboard and shell failures produce visible toast feedback.
- Letter-only hidden shortcuts from the legacy menus are removed; visible keyboard navigation remains the browser's native focus behavior, with Escape closing the menu.

## Test plan

- Pure menu-model tests lock the ordered action groups and prove archive is absent from both inventories.
- Pure placement tests cover left/top and right/bottom viewport clamping.
- Focused renderer lint/typecheck/build verifies the shared menu component and both consumers.
- Human verification opens project and task menus in the running Electron development build, tests every enabled action family, and compares both menu states against the supplied screenshots.

## Acceptance criteria

- Project and task menus visibly share the same elevation, radius, row height, typography, hover, divider, and viewport behavior.
- Project menu contains exactly pin, file-manager, rename, and remove actions.
- Task menu contains exactly pin/read state, rename, file-manager, working-directory copy, conversation-ID copy, continue in new task, and delete actions.
- Neither menu contains Archive/Unarchive or an `archived` mutation.
- No enabled row is a placeholder.
- Existing rename, fork, delete, and project-remove behavior remains functional.
- Unit tests, typecheck, lint, renderer build, and visual QA pass.

## FEATURE_145: Cross-Platform Attention Badge

### 1. 需求概述

KodaX Space 在存在未读 Session 结果或等待用户处理的权限/问答请求时，应在操作系统原生应用图标上显示数字角标。Windows 使用任务栏覆盖图标，并在 Space 关闭到通知区域后保持同一计数；macOS 使用 Dock 数字角标；Linux 使用 Electron 支持的启动器数字角标并在桌面环境不支持时安全降级。

角标统计需要注意的唯一 Session 数，而不是事件、Toast 或消息条数。同一 Session 同时存在未读结果、权限请求和 Ask User 请求时只计一次。用户查看并聚焦该 Session 后清除未读结果；待处理请求仅在实际解决或取消后退出计数。

### 2. 影响范围

- `packages/space-ipc-schema/src/channels/window.ts` 与注册表/测试：新增有界、类型化的角标计数 IPC。
- `apps/desktop/renderer/src/features/notifications/`：从现有 Session 未读标志和交互队列派生唯一注意力 Session 数，并只在计数变化时同步。
- `apps/desktop/renderer/src/store/appStore.ts`：后台失败结果与后台完成结果共享未读语义，用户取消不制造未读。
- `apps/desktop/electron/window/` 与 `apps/desktop/electron/main.ts`：实现平台适配、Windows 16px 覆盖图标和通知区域图标刷新。
- 相邻单元测试：覆盖计数去重、IPC 边界、平台分派、图标位图和终态未读行为。

### 3. 技术方案

- 复用现有 renderer `sessionFlags.unread`、`permissionQueue` 和 `askUserQueue`，不建立第二个通知存储。
- renderer 通过 `window.setBadgeCount` 仅发送 `0..9999` 的整数；main 进程是唯一 Electron API owner。
- Windows 调用 `BrowserWindow.setOverlayIcon`。覆盖图标由固定 3×5 点阵数字生成，1-9 显示数字，更多显示 `9+`；通知区域图标在基础 Space 图标右下角合成同一标记。
- macOS/Linux 调用 `app.setBadgeCount`。Linux 以 Electron/桌面环境返回值为准，不伪造全平台支持。
- main 保存最近计数，使窗口或 Windows Tray 重建后能立即恢复当前角标；计数为 0 时清除覆盖并恢复基础 Tray 图标。

### 4. 接口契约

```ts
window.setBadgeCount({ count: number }) -> { applied: boolean }
```

- `count` 必须是 `0..9999` 的整数。
- `applied` 表示当前平台至少一个原生目标接受了更新；不支持的 Linux 桌面返回 `false`，不得抛出或影响 Session 工作。
- IPC 不接受图像、标题或任意平台参数，避免 renderer 控制原生图标内容。

### 5. 实现步骤

1. **F145-T1 — Attention projection and IPC contract**：测试先行地定义唯一 Session 计数与 `window.setBadgeCount` schema/allowlist。
2. **F145-T2 — Native platform adapter**：测试先行地实现计数规范化、Windows 数字位图、任务栏/Tray 更新和 macOS/Linux 分派。
3. **F145-T3 — Lifecycle integration**：接入 renderer 订阅、窗口/Tray 重建刷新、后台失败未读语义，并运行相关回归测试。
4. **F145-T4 — Release-quality gate**：执行全量 test、typecheck、lint、build，并按 Standards/Spec 双轴评审本次 diff。

### 6. 验收标准

- 一个或多个未读/待处理 Session 产生正确的唯一计数；同一 Session 的多个来源不会重复计数。
- 当前可见且聚焦的 Session 完成或失败不增加角标；后台完成或非取消失败增加，查看 Session 后减少。
- 权限和 Ask User 请求在等待期间计入，解决/取消后移除。
- Windows 主窗口显示数字覆盖图标；关闭到通知区域前后的图标计数一致；清零后恢复原图标。
- macOS Dock 和受支持 Linux launcher 使用原生数字；不支持的 Linux 环境安全返回 `applied:false`。
- IPC 拒绝负数、小数、超界值和额外字段；所有新增行为有单元测试，且现有测试、类型检查、lint、build 全绿。

## Maintenance: Previous-Boot Windows ACL Recovery

Space continues to delegate all ACL ownership and recovery decisions to
`settleKodaXRuntimeExit()`. Published KodaX 0.7.93 may converge multiple foreign
markers only after a verified Windows boot change and a machine-lock recheck
prove that every marker has a canonical non-current boot identity. Same-boot,
mixed, missing-identity, corrupt, and concurrent current-boot states remain
blocked. Both Space manifests and the lockfile pin the audited 0.7.93 Registry
package and integrity.

Space does not call Setup or activation during startup. A blocked settlement is
projected into localized restart/support steps and a main-process “Open
diagnostics folder” action available on the blocking boot surface. The reported
`ACL recovery ... foreign or unverifiable owner marker` wording is recognized as
an ACL recovery block and is not echoed with raw marker details.

## Maintenance: Background Exit and Quiet Success

After visible active-work, owner, and Runtime preflight admits complete exit,
Windows hides the main window and continues the same SDK settlement through the
tray. Reopening Space restores the same elapsed progress. A clean/recovered
result exits without an ordinary system notification; a failure restores the
window and actionable diagnostics. The settlement owner, timeout, recovery
ticket, Job/ACL rules, and cross-client safety remain unchanged.

## Maintenance: Canonical and Live Activity Alignment

- Canonical page-head selection remains stable when older live turns arrive
  while history is converging.
- Task Dock projects current live Agent/Workflow activity without letting an
  older snapshot hide active work or retain completed work.
- Runtime repo-intelligence traces reach the Repointel status chip through the
  existing bounded projection; Space does not create another Runtime store.
- Persisted Sessions with no External Agent tasks render a normal empty state;
  real list failures are retryable and do not change the main Run result.

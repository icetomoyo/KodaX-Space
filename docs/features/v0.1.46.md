## FEATURE_274: 结算认证身份化（turnId presence + 源静止放行）

### 1. 需求概述

**问题**：Run 结束后 Space 决定 canonical 历史页能否接管该轮显示的认证机制，此前基于时序/代数证据（generation 计数、读次序）。用户可见后果即 Issue 204：第二轮回答 agent 实际已产出，但 raced 的认证把已画内容交给缺 assistant 行的 canonical 壳，Ctrl+R 才能找回。202/204/205 的反复修补同根：认证靠猜时序，每种竞态都是一种新的猜错方式。

**方案**（决策记录见 [ADR-009](ADR/ADR-009-settlement-certification-identity.md)）：把认证锚在身份证据上——

1. terminal-scoped newest 页包含 `kind !== 'user'` 且 `turnId` 匹配该 terminal Run 的条目，该读才认证该 Run（身份确认）；
2. 身份未确认时，连续两次 `page.revision` 相同（持久化已收敛）仍无该 turn 的行 → 结构性放行（出错轮次本无可持久化内容），至多多 1 次重读；
3. `decideTurnProjectionAuthority` 的空 durable 内容守卫（Issue 204 修复）永久保留为独立兜底不变式；
4. 其余情况保持现有重试梯与 fail-open，不新增错误态。

### 2. 影响范围

- `apps/desktop/renderer/src/store/runtimeProjectionState.ts` — `RuntimeTerminalEvidence` 增加可选 `turnId`；live/profile 两个构造点补齐；新增纯函数 `terminalEventEvidence`（把 App.tsx 直连 terminal 事件的证据构造提为可单测纯函数，含从 fresh live `lastTerminalRun`（runId 匹配）补 turnId）
- `apps/desktop/renderer/src/shell/sessionHistoryPaging.ts` — 证据组与 request scope 每 run 携带 `turnId` + `lastSeenRevision`；`completeTerminalHistoryRequestScope` 身份感知完成判定
- `apps/desktop/renderer/src/App.tsx` — 直连事件证据改用 `terminalEventEvidence`
- 测试：`apps/desktop/electron/test/session-history-paging.test.ts` 新增决策分支用例；`runtimeProjectionState` 证据构造用例
- 文档：`docs/ADR/ADR-009`、`docs/KNOWN_ISSUES.md`（204/205 交叉引用）、`CHANGELOG.md`

### 3. 技术方案

- 纯 renderer 行为，零 SDK/IPC/主进程语义改动；`spaceRuntimeRunProjectionSchema.turnId`、`SessionHistoryItem.turnId` 均为既有字段，无 schema 变更。
- 失败方向全部 fail-open：turnId 缺失 → presence 检查跳过（现状行为）；源静止两次后仍无行 → 放行；重试梯上限（30 次 → phase error → 回 pending）不变。
- mock 路径（`KODAX_FORCE_MOCK`）无 runtime 证据，不进认证链，e2e 行为不变。

### 4. 接口契约

```ts
// runtimeProjectionState.ts
interface RuntimeTerminalEvidence {
  readonly sessionId: string;
  readonly runtimeId: string;
  readonly runId: string;
  readonly phase: string;
  readonly cursorSeq: number;
  readonly startedAt?: number;
  readonly completedAt?: number;
  readonly transcriptRevision?: string;
  /** 该 terminal Run 产出 turn 的身份；缺失 = presence 检查跳过（fail-open）。 */
  readonly turnId?: string;
}

/** App.tsx 直连 terminal 事件的证据构造：runtimeEvent origin 无 turnId，
 *  从 fresh live 投影的 lastTerminalRun（runId 匹配）补齐；补不到为 undefined。
 *  runtimeEvent 缺失 / 连接非 fresh / origin runtime 不匹配 → undefined，
 *  调用方回退 authoritative 候选路径。 */
function terminalEventEvidence(input: {
  readonly kind: 'session_complete' | 'session_error';
  readonly sessionId: string;
  readonly runtimeEvent:
    | { readonly runtimeId: string; readonly runId: string; readonly seq: number }
    | undefined;
  readonly connection: SpaceCoderConnectionProjectionT;
  readonly liveBySession: Readonly<Record<string, SpaceSessionLiveProjectionT | undefined>>;
}): RuntimeTerminalEvidence | undefined;
```

```ts
// sessionHistoryPaging.ts（模块内部状态）
interface TerminalHistoryWorkflowGroup {
  readonly runtimeId: string;
  readonly nextGeneration: number;
  readonly runs: readonly {
    readonly runId: string;
    readonly generation: number;
    readonly status: 'pending' | 'in-flight' | 'completed';
    readonly turnId?: string;
    /** 上次身份未确认尝试时的 page.revision；两次相同 = 源静止 → 结构性放行。 */
    readonly lastSeenRevision?: string;
  }[];
}

// run 完成条件（completeTerminalHistoryRequestScope，在既有 generation/runtimeId 棚栏之上）：
//   无 turnId            → 本次读即完成（现状）
//   turnId 身份在页内     → 完成（存在 kind !== 'user' 且 item.turnId === run.turnId 的条目）
//   page.revision === run.lastSeenRevision → 结构性放行完成
//   其余                  → 记录 lastSeenRevision，保持 pending → 现有重试梯
```

### 6. 验收标准

- 用户故事：一轮回答完成后立即追问，已显示的回答不消失、无需 Ctrl+R 找回；Runtime 结算与渲染竞速时最终内容与 canonical 一致（不重复、不丢行、不空壳）；出错轮次（无 assistant 输出）结束时 UI 立即恢复，不卡加载；加固不引入可感知的结算/切换延迟（至多 1-2 次有界重读）。
- 单测决策分支（session-history-paging.test.ts，TDD 先红后绿）：turnId 身份在页内 → 该读 settle；页内无匹配 → 保持 pending 重读；连续两次同 revision 仍无 → 结构性放行 settle；revision 前进 → 继续 pending；无 turnId 证据 → 一次读 settle（现状）。第 6 分支（turnId/lastSeenRevision 穿越 scope 重捕保留）由结构性放行用例隐式覆盖——其第 3 次读依赖第 2 次记录的 lastSeenRevision 穿过 scope 重捕。
- 证据构造用例：live/profile 证据携带 `lastTerminalRun.turnId`；`terminalEventEvidence` 从 live 补齐 turnId、无 fresh live 时不带 turnId。
- 回归硬门：现有 session-history-paging / history-replay-no-popout / history-order-regression 等历史单测全绿；`tsc -p apps/desktop` 与 electron tsconfig 零错误。
- e2e：mock Playwright 套件全绿；r6 真机 Issue 204 复现场景在 provider 恢复后补跑（已知环境阻塞，不阻塞合入）。

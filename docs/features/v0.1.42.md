# KodaX Space v0.1.42 — Causal Transcript and Latest KodaX Alignment

> Status: Release candidate; final status and CI evidence are recorded in the [release-readiness record](../releases/v0.1.42-release-readiness.md).
> Date: 2026-08-16
> Scope: exact package metadata, KodaX 0.7.88 alignment, renderer causal reconciliation, user-facing lifecycle feedback, and complete documentation/manual synchronization.

## Release intent

v0.1.42 packages the maintenance and stabilization work already present on the
source line and aligns Space with the latest npm `@kodax-ai/kodax` release.
The npm registry reports `0.7.88` as `latest`; every Space manifest and the
lockfile pin that exact published package.

This is a compatibility, transcript-integrity, and release-documentation
update. Release preparation does not add a new system business rule or a new
KodaX SDK contract.

implicitly through a range.

## Runtime and transcript boundaries

KodaX 0.7.88 supplies `actorSettlementConvergence:2`. Space requires that
capability from both the installed SDK and the connected Runtime, so legal
storage admission waits, canonical replacement, and post-commit maintenance
remain distinct outcomes. A v1 daemon is rejected instead of being reused by a
v2 Space build.

Space-side renderer reconciliation keeps the existing identity-first and
fail-open boundaries:

- canonical/live leading-page reconciliation moves an earlier live prefix and
  its event segment together;
- terminal Runtime events bind only to an exact Run/Turn owner or a proven
  causal snapshot boundary;
- continued Runs reset draft ownership at each root `turn.started` boundary;
- delayed old terminals cannot close a newer query or settle its completion
  notification;
- explicit create-time provider/model choices survive daemon admission;
- ambiguous, missing, foreign-epoch, or legacy identity stays visible or
  fail-closed instead of being guessed from timestamps or text.

No timestamp sorting, content-based deduplication, synthetic SDK event, or
business-logic fallback is introduced by the release preparation.

## User-facing maintenance

- Auto[LLM] approval prompts show a bounded, sanitized classifier reason while
  keeping prompts, full responses, and credentials private.
- Session deletion shows an in-flight state, prevents duplicate actions, and
  performs the collapse/removal animation only after backend confirmation.
- The Chinese user manual and in-app `kodax_manual` describe KodaX 0.7.88,
  Actor settlement v2, exact owner reconciliation, Session feedback, and the
  current troubleshooting boundary.

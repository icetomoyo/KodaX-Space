# KodaX Space v0.1.43 — Crash-Resumable Complete Exit

> Status: implemented maintenance baseline
>
> Date: 2026-08-17
>
> Dependency: exact audited npm Registry `@kodax-ai/kodax@0.7.92` bytes

## Problem

An idle Space could accept a daemon stop, fail to verify Runtime cleanup, and
relaunch with only a boolean recovery flag. The relaunched process initialized
owner reconciliation and the daemon normally; it had no exact operation fact
with which to finish the prior exit. The old adapter had already closed its
Runtime projection, so Session content could temporarily report
`runtime_unavailable` even though no visible task was running.

The triggering v0.7.88 workspace-session timeout was fixed in KodaX 0.7.90,
but that did not recover an already stranded same-boot Windows owner. The SDK
audit also found that daemon final cleanup capped a documented 15-second hidden
memory-review drain at two seconds and could not cover the 130-second sandbox
reset contract, so an apparently idle Runtime could still record cleanup
failure. KodaX 0.7.91 aligns those orderly-cleanup deadlines.

## Architecture

Space delegates complete-exit lifecycle ownership to the public SDK
`settleKodaXRuntimeExit()` transaction. Space does not read, write, or infer
daemon locks, Job metadata, ACL markers, process identities, or recovery
tickets.

Normal exit:

1. Space drains its admission boundary and preserves the existing local/other
   client checks.
2. The adapter passes the live Runtime plus exact config/profile to the SDK.
   Space cannot override the SDK's fixed transaction or orderly-cleanup
   deadlines.
3. `blocked/keep-open` restores the existing visible app; `clean` or
   `recovered` completes quit; a post-mutation block relaunches visibly.

If Session/Runtime initialization has already failed, Space first asks the SDK
to resume any ticket. When no stop was accepted, it opens a management-only
Runtime connection with `autoStart:false`, initiates the same SDK settlement,
and closes that temporary client. It never falls back to the racy CLI stop path
or starts a replacement daemon just to exit.

Recovery relaunch:

1. Electron recognizes `--space-runtime-exit-recovery`.
2. Before owner-policy reconciliation or daemon initialization, it calls the
   SDK without a Runtime object to resume the durable ticket. An ambiguous
   `prepared` ticket reconnects only the existing management plane with
   `autoStart:false` and reuses the stable ticket with a fresh stop attempt.
3. `clean/recovered` finishes the original quit. `keep-open` continues normal
   startup. Every other blocked result stops startup before a replacement owner
   can be created and shows the SDK recovery guidance.

Daemon-mode startup also performs the same ticket scan when no recovery flag
survived (for example, after a hard process kill or system restart). A recovered
ticket then continues the user-requested normal launch; an unresolved accepted
ticket still blocks owner reconciliation. Embedded-mode startup skips this scan
unless it is explicitly handling a daemon exit recovery relaunch.

## Compatibility

- Space requires the local SDK capability `runtimeExitSettlement:1`; this is
  not a connected-daemon capability requirement.
- Space also requires pre-start and connected `sandboxRuntime:4` plus
  `crashOutcomeModel:2`. These reuse the SDK's existing fenced idle-daemon
  upgrade; Space does not own lock reclamation, native fallback, terminal
  synthesis, or daemon killing.
- Windows can return `recovered` only from exact identity and Job-empty proof;
  matching ACL markers are repaired when present, but zero-marker lifecycle
  recovery is also valid.
- macOS/Linux clean exits remain supported. A stuck retained daemon remains
  visibly blocked during the same boot and is never signaled through cached
  PID/PGID identity. After an OS reboot changes the durable boot identity, the
  retained ticket is settled autonomously before owner reconciliation.
- Embedded Partner/compatibility ownership and all existing admission,
  active-work, other-client, and renderer/session contracts remain unchanged.

## Packaging gate

The package smoke requires the installed package metadata and runtime facade to
publish `runtimeExitSettlement:1` and `settleKodaXRuntimeExit`. Its daemon
lifecycle probe performs both initial and restarted-daemon shutdown through the
new public API. A hidden packaged-Electron E2E separately drives the real
`requestCompleteExit` product path twice, proves Space/daemon/Job ownership is
gone, relaunches the same isolated profile, and reads the persisted Coder
Session history without `runtime_unavailable`.

## Acceptance

Automated adapter and startup-decision tests cover clean/recovered/block/keep-
open routing, failed-initialization and ambiguous-prepared management reconnect,
late-stop attach races, reconnect suppression, bounded duplicate transport
close, and the actual settlement → owner reconciliation → Runtime
initialization boundary.
The packaged-Electron E2E also covers the end-to-end quit and Session reload
boundary rather than only calling the SDK from a standalone Node probe.

## 1. Release decision

`v0.1.34` is the verified stabilization release after published `v0.1.33`. It
ships:

- explicit KodaX 0.7.78 Runtime safety/capability negotiation;
- last-known-good MCP/A2A/Extension configuration and visible integration
  health;
- Auto guardrail v4 retry and one-call fallback semantics;
- structured active-tool sandbox/fallback facts;
- physical packaged ASRT/sandbox helper resolution;
- cross-platform complete exit and Space-scoped orphan-idle recovery;
- one main-owned startup/shutdown overlay;
- exact positional history replay after completed interrupt runs; and
- updated README, user/developer manuals, PRD, HLD, capability ledger,
  Feature List, Known Issues, changelog, and `kodax_manual`.

This release does **not** claim the F137/F139 native document/semantic UI lane.
That reviewed design moved intact to `v0.1.36`.

The initial full test run restored `better-sqlite3` from the Electron ABI to
the Node 22 ABI before executing the Desktop suite. That expected rebuild log

The repository-wide `npm run format:check` still reports 304 pre-existing
formatting mismatches, mostly historical documentation and vendored builtin
Skill assets outside this candidate. Reformatting that entire baseline would
mix hundreds of unrelated mechanical changes into the release. The release
therefore formats and checks every changed/added candidate file while keeping
the full-repository baseline explicit.

The first Windows E2E pass found one stale test assumption: Playwright exposes
the new boot `WebContentsView` as a short-lived Page, so the tray-reopen test
raced that overlay instead of selecting the `app://space/` BrowserWindow. The
fixture now selects the main renderer by URL and waits for atomic overlay
removal. The focused scenario passed once, then 3/3 repeated runs, followed by
the full 74-pass suite.

The first GitHub E2E candidate exposed a second early-page race in the dedicated
startup-overlay spec: its `onLaunched` hook evaluated the main process while
Playwright was still replacing the boot `WebContentsView` execution context.
The assertion now runs only after the fixture selects `app://space/`, atomically
checks second-instance activation, and holds both overlay phases for a
deterministic window. The scenario passed 3/3 locally and then passed in both
GitHub Windows/Linux shard 2 jobs.

The macOS packaged-daemon preflight also exposed Darwin's 104-byte Unix-socket
path limit. KodaX 0.7.78 correctly requires auto-start to use its profile
default endpoint, so Space temporarily normalizes Darwin `TMPDIR` to `/tmp`
only while the SDK computes/spawns that endpoint and restores the host
environment afterward. Both macOS arm64 and Intel packaged Runtime lifecycle
smokes pass with this compatibility layer.

## 8. Manual and known-risk record

Automated release approval does not erase these explicit boundaries:

- F121 still requires its separately recorded final human multi-client
  acceptance ledger.
- Issue 133 remains `In Progress` for packaged macOS/Linux process-level exit
  acceptance and KodaX 0.7.78's asynchronous orphan-cleanup
  retry/verification gap.
- `daemonOrphanExit:1` proves that the current host enabled orphan idle-exit; it
  does not expose a pre-existing daemon's effective grace interval or guarantee
  retry after every asynchronous cleanup failure.
- KodaX command containment and packaged helpers do not complete F138's
  document staging, credential, native-resource, and cross-platform OS
  isolation.
- Unsigned macOS/keychain behavior remains tracked separately; publication
  does not imply code signing or notarization.

These are documented limitations, not hidden substitutions. Any new release
workflow failure is a blocker and must be fixed before publication.

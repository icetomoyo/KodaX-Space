# v0.1.46-alpha.10 release readiness

Date: 2026-09-11. Previous release: v0.1.46-alpha.9.

## Scope

- Pin the published KodaX 0.7.96-beta.6 in root/Desktop manifests and the lockfile (beta.5 and
  beta.6 both retained; one deduplicated hoisted Registry copy, and the stale nested
  `apps/desktop/node_modules/@kodax-ai/kodax` beta.4 entry is dropped again).
- Follow the SDK's DeepSeek catalog change: the built-in `deepseek` alias speaks the official
  `api.deepseek.com/anthropic` wire, the default model is `deepseek-flash` (1M context, 384,000
  max output, native image input), `deepseek-v4-pro` stays selectable, and
  `deepseek-v4-flash-vision-exp` left the SDK catalog. Space's catalog override protocol becomes
  `anthropic` and its disaster-fallback default model becomes `deepseek-flash`
  (`provider-catalog.test.ts` guards the new shape).
- Track the SDK's beta.5 Windows sandbox setup generation 11 (Issue 333 Codex-compatible
  profile/SSH ACL exclusions) and beta.6 prompt-cache wire-truth diagnostics in the capability
  ledger, user manual, kodax_manual, and version comments. Wire protocol 10 and every public
  capability version are unchanged, so no Space gate moves.
- Synchronize workspace versions, capability contract string, changelog, READMEs, capability
  ledger, product/architecture/usage docs, user manual, feature list, and kodax_manual.

## Qualification

Typecheck passed; application lint passes with zero warnings (the only local lint errors live in
untracked `scratch/` diagnostics that CI never sees). The full unit suites passed with 0 failures:
the release-gate scripts suite 48/48, the desktop suite 2936 passed / 13 skipped (2949 total) with
the compat gate expecting beta.6 and the catalog/manual-topic expectations moved, and the
ipc-schema workspace suite 317/317. The published-package compatibility suite ran inside the
desktop suite against the installed beta.6 tarball, including the shared multi-client daemon
probe, the Worker isolation probe, the fail-closed sandbox facade check, and the Auto[LLM]
capability constants.

The installed SDK's README, Chinese README, changelog, and shipped `public_docs` match the
`v0.7.96-beta.6` source tag byte-for-byte (modulo EOL normalization). The lockfile resolves one
hoisted beta.6 copy at the exact Registry URL/integrity
(`sha512-PDHPahGJ2dpivBovMkJO6pOTtK0ZO52SzhClXLdLExp8I05utXoI3dgu7o2kmDhGpN7m0jjvQp8vRIS0WXCH1w==`).
`provider-capabilities.json` changed only in the `deepseek` entry (`updatedAt` 2026-09-10); all
other providers are byte-identical to beta.4.

## Remaining boundaries

This alpha delivers no new Space control: compaction summary telemetry, permission profiles,
credential scopes, and sandbox doctor/setup surfaces are unchanged from alpha.9. Per-request
compaction metrics stay SDK-owned. The DeepSeek wire change is consumed through the SDK's own
provider implementation — Space never opens provider connections itself, so no Space-side
endpoint configuration is introduced.

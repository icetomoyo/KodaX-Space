   missing, or byte-different files must fail the release.

   `created by huashu-design`, `huashu · design`, Huashu HTML wordmarks, nor
   the promotional demo URL; demo finales must use neutral `YOUR BRAND`
   placeholders while the upstream MIT license and authorship remain
   distributed.

## 7. Post-release repair and stop conditions

Before the stable tag was created, publication would stop if any required
capability was missing, package contents differed from their integrity locks, a
platform artifact could not boot, a background interaction could be consumed by
the wrong Session, the builtin watermark reappeared, the Windows live window
still showed a generic taskbar icon, query-time console windows still flashed,
the tray left an invisible resident owner or force-stopped shared work, or the
release staging script could not assemble the exact asset matrix.

Because the stable tag automatically creates a public release, the preferred
rollback is to fix the candidate before tagging. If a tag-triggered workflow
fails, do not reuse or silently move the published tag; diagnose the failed job,
prepare a reviewed corrective commit, and follow the project's explicit release
repair policy.

## Release decision

`v0.1.35` consumes the published KodaX 0.7.80 package without a vendored
runtime patch. It adds one explicit compatibility gate,
`managedRunDurability:1`, and makes Space consume the resulting durable Run
identity rather than inferring correctness from a package version.

The release includes:

- exact Registry tarball resolution and lockfile SRI for KodaX 0.7.80;
- fail-closed daemon and SDK capability negotiation for durable managed Runs;
- confirmed `runId` plus streamed `turnId` binding for optimistic composer
  queries and history refreshes;
- Auto LLM timeout forwarding that preserves user values and otherwise uses
  KodaX's 45-second initial and 90-second retry defaults;
- matching README, Chinese manual, developer docs, PRD/HLD, capability ledger,
  feature list, changelog, test guide, and in-app `kodax_manual`; and
- regression coverage for capability negotiation, runtime compatibility,
  composer admission, history paging, and manual text.

`worker.configuredA2A` is documented as a KodaX CLI Worker-hosted embedded
Runtime configuration. It is deliberately not surfaced as a Space runtime-mode
or Settings control.

## Explicit boundaries

- The compatibility check is capability-based; semantic version text alone does
  not admit a daemon.
- Durable persistence is owned by KodaX. Space binds and projects the returned
  identities; it does not implement a second Run store.
- KodaX's 500-iteration managed-run panic fuse and recovery transcript remain
  SDK behavior. Space only exposes the resulting normal Runtime events.
- Full F117 memory Episodes/Activity/correction/purge UX and the F121 final
  human multi-client acceptance ledger remain separately scoped work.

# v0.1.46-alpha.9 release readiness

Date: 2026-09-08. Previous release: v0.1.46-alpha.8.

## Scope

- Pin the published KodaX 0.7.96-beta.4 in root/Desktop manifests and the lockfile.
- Adopt beta.4's shared `compaction.reasoning` summary policy through the existing shared
  Session settings v2 contract; Space keeps the SDK default and adds no new control.
- Surface bounded compaction summary telemetry (`summaryRequestCount`, `commitMs`) through the
  `compact_stats` IPC contract for both the Runtime finished event and the embedded manual
  compact path; the context gauge shows the request count only when map/reduce fans out.
- Fix the v0.1.45 composer regression: slash commands clear the input at submit time with a
  submit-time attachment snapshot; the compacting spinner stays centered in the context gauge
  (regression e2e `tests/e2e/compact-composer.spec.ts` with the `SPACE_TEST_COMPACT_DELAY_MS`
  deterministic hold).
- Synchronize workspace versions, capability contract string, changelog, READMEs, capability
  ledger, product/architecture/usage docs, user manual, feature list, and kodax_manual.

## Qualification

Typecheck passed; application lint passes on all changed sources (the only remaining lint
errors live in untracked local `scratch/` diagnostics). The full desktop unit suite passed:
2948 tests, 2942 passed, 5 skipped, 0 failed after the manual-topic version expectation moved
to beta.4. The published-package compatibility suite passed 9/9 against the installed
beta.4 tarball, including the shared multi-client daemon probe, the Worker isolation probe,
the fail-closed sandbox facade check, and the Auto[LLM] capability constants.

Release commit 148ebb2e verified green on GitHub (2026-09-08): [build](https://github.com/icetomoyo/KodaX-Space/actions/runs/34234955282) and [CI](https://github.com/icetomoyo/KodaX-Space/actions/runs/34234955213) 4/4 E2E shards passed on the first run; the [release](https://github.com/icetomoyo/KodaX-Space/actions/runs/34234955453) workflow needed two `--failed` retries of the Windows installer job. The identical tag content passed the complete local Windows product-smoke path (`pack.mjs --win`: smoke-pack 60/60 including the packaged Worker/containment probe, boot smoke, and the complete-exit smoke "two product exits clean"), so the retries were runner-environment flakes in the sandbox/WFP-probe area — attempt 1 failed the packaged daemon exit settlement with `containment_unavailable`, attempt 2 failed sandbox setup with a `wfp_probe_timeout` ETIMEDOUT, attempt 3 passed all gates. `srt-win.exe` and the bundled `@anthropic-ai/sandbox-runtime@0.0.65` are byte-identical between beta.3 and beta.4, confirming the flake is not a beta.4 native regression. Published assets match the v0.1.46-alpha.8 manifest shape (18 assets across Windows/macOS/Linux plus `latest*.yml` updater manifests pointing at 0.1.46-alpha.9).

beta.4 is a telemetry/summary-policy prerelease: `provider-capabilities.json` is byte-identical
to beta.3 and every public capability version is unchanged (`sandboxRuntime:11`,
`runtimeAutoModeGuardrail:5`, `sharedSessionSettings:2`, `providerCredentialBroker:2`,
`effectiveConfig:1`). The lockfile now resolves one hoisted SDK copy; the stale nested
`apps/desktop/node_modules` entry pinned to beta.3 was dropped. Release links and CI gates are
unchanged; the tag-triggered release workflow rebuilds and republishes installers from the tag.

## Remaining boundaries

This alpha does not deliver FEATURE_275. `compaction.reasoning` is not exposed as a Space
setting — the SDK default (thinking disabled where supported; side-query low-effort resolver on
always-thinking models) governs. Per-request compaction metrics (provider/model/timings/usage)
stay SDK-owned and never cross IPC; Space carries only the count and commit duration.

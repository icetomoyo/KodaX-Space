# v0.1.46-alpha.11 release readiness

Date: 2026-09-13. Previous release: v0.1.46-alpha.10.

## Scope

- Pin the exact published KodaX 0.7.96-rc.1 candidate in root/Desktop manifests and the lockfile,
  superseding the beta.8 source baseline. Root/Desktop manifests, lockfile, installed bytes,
  packaged ASAR, and the fully unpacked universal native bundle continue to resolve one Registry
  URL and integrity; Space consumes the exact Registry bytes without patching them.
- Require Runtime permission authority v6 (`runtimeAutoModeGuardrail:6`) at startup, daemon
  negotiation, and packaging. Embedded runs pass their bound permission mode to SDK text
  authority and model context so Runtime and direct-SDK text writes agree. Real SDK regressions
  cover approved Auto writes outside the workspace, direct Full Access writes, denial isolation,
  and live mode changes.
- Adopt rc.1 runtime controls: Session Stop frontiers (one stop cancels the owner's queued
  frontier while later Runs survive; result-unknown stops keep the original Session/Run/requestId
  retry identity; retries are refused after a terminal Run without an owner receipt), managed
  extension and explicit `!command` Runs through the normal Run path (configuration-only
  extension commands stay CLI-owner-only), and `/repair-identity` explicit audited history
  identity repair with owner-level cancellation regression coverage and F274 acceptance guidance.
- Land FEATURE_275 tickets 1-6, the identity-anchored transcript model: canonical history pages
  plus a transient live tail feed a derived view with explicit input/output ownership, compose
  user slots order on explicit sortKey instead of mixed sentAt clocks, exact retirement receipts
  reject journal replay and snapshot sidecars, receipts and overlapping newest pages stay
  bounded, and expired evidence fails open toward preserving content. Includes the
  refresh-equivalence property test and golden lifeline fixtures.
- Verify the installed rc.1 release through direct and managed multimodal reads, `tool_call`,
  allowing guardrails, native child execution, capacity spill, and local failure propagation
  (F121 regression guide).
- Fix packaged boot to retain restart-stable Runtime client credentials in an isolated test
  keyring namespace; preserve readable history on `identity_repair_invalid` and structured
  `local_execution` failures without provider-setup suggestions or automatic retry.
- Keep CI green on cold Windows runners: the release-gate suite now warms the KodaX native
  artifact cache through one throwaway Runtime write before unit tests (rc.1's protected write
  path provisions its text-transaction binding through a PowerShell helper with a hard 30s
  budget, which Defender contention on fresh runners turned into silent write ENOENTs in
  `kodax-permission-authority` and `kodax-runtime-control`).
- Synchronize workspace versions, changelog, READMEs, capability ledger, product/architecture/
  usage docs, user manual, feature list, `docs/features/v0.1.46.md`, and kodax_manual.

## Qualification

Typecheck passed; the full unit suites passed with 0 failures, including the release-gate
scripts suite, the desktop suite with the rc.1 compatibility gate and permission/runtime-control
probes running against the installed published SDK, and the ipc-schema workspace suite.
`docs/features/v0.1.46.md` and the F030/F121/F275 guides describe the human acceptance passes
for permission authority v6, multimodal fidelity, and transcript ownership.

## Remaining boundaries

FEATURE_275 tickets 1-6 do not close every long-term acceptance goal: guaranteeing bounded
memory together with replay that never resurrects unknown inputs still requires SDK/main-side
persistent exact identity queries or a full delivery-batch coverage proof; current terminal,
cursor, and queuedInputs evidence is not that proof, and conflicts keep failing open toward
preserving content. No new Space control ships in this alpha: compaction summary telemetry,
permission profiles, credential scopes, and sandbox doctor/setup surfaces are unchanged from
alpha.10. Configuration-only extension commands have no public daemon execution endpoint in
rc.1 and remain with the CLI owner.

Published rc.1 daemon transports negotiate the Session Stop protocol surface as
`runLifecycleControl` and cannot yet serve the embedded facade's `sessionCancellation` frontier
operation to daemon clients (the packaged dependency smoke asserts the negotiated
`runLifecycleControl` surface). Space therefore stops the exact bound Run through `runs.abort`
on daemon owners — restoring the alpha.10 stop behavior — while the frontier retry identities
from F274 apply on embedded owners where the SDK publishes the frontier operation.

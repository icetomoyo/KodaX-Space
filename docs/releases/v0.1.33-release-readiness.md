## 1. Corrected release scope

The replacement `v0.1.33` keeps the same product and SDK versions while adding the corrections
required after withdrawal:

- exact Registry KodaX 0.7.77 and Node 22 toolchain alignment;
- canonical Agent Actor/Turn projection and monotonic Runtime/history reconciliation;
- root context, cumulative Session usage and prompt-cache diagnostics;
- shared Shell/profile-PATH behavior for Terminal and Coder command tools;
- F140 configurable main-window close behavior;
- F141 customer-selectable recommended Daemon / Embedded compatibility owner with one admission
  boundary, complete blockers, startup reconciliation, compensation, and restart;
- F142 conversation file actions;
- visible sent/restored image attachments and unambiguous context/compaction state;
- KodaX 0.7.77 split MCP/Extension/A2A configuration, SDK-backed non-destructive migration, and
  Settings source truth;
- preservation of every SDK-recommended underlying `kodax_manual` topic, including exact original
  body, aliases, and sources beneath same-id Space overlays; and
- Registry-only packaging, complete dependency closure, packaged native SQLite load, public-facade
  imports, and a real packaged application boot.

It does not update KodaX beyond 0.7.77, consume a local unpublished SDK, migrate Partner into the
Coder daemon, provide live owner failover, ship F137 document authoring, or claim signed/notarized
installers.

## 8. Known and accepted boundaries

- Installers are unsigned; Windows SmartScreen and macOS Gatekeeper may prompt.
- Partner remains Space-owned embedded inline.
- Invalid optional integration config isolation remains open for a future published KodaX contract;
  the 0.7.77 release documents non-destructive repair/migration and does not claim automatic
  recovery.
- The packaged Electron nested shell-helper issue remains deferred upstream; no unpublished SDK fix
  is represented as part of this release.
- F137 document authoring and F139 semantic UI polish remain planned for `v0.1.34`.
- Unexecuted manual journeys remain unchecked after publication.

## 9. Publication sequence

1. Complete code, documentation, `kodax_manual`, and Known Issues updates on `main`.
2. Remove local KodaX staging, install exact Registry 0.7.77, run every local gate, and record facts.
3. Split and commit changes by function; confirm the worktree is clean.
4. Push `main` non-interactively with the configured PAT; wait for `ci` and `build` to pass.
5. Delete the withdrawn GitHub Release and old remote/local `v0.1.33` tag.
6. Create the corrected annotated `v0.1.33` tag at the reviewed main commit and push it.
7. Wait for the four-platform release workflow and replacement GitHub Release.
8. Verify every asset/updater manifest, record new run URLs and SHA-256 values, commit the evidence,
   push `main`, and wait for final `ci`/`build` to pass.

## 1. Release scope

`v0.1.33` stabilizes the `v0.1.32` shared-daemon and Partner-knowledge baseline:

- exact Registry KodaX 0.7.77 and Node 22 toolchain alignment;
- canonical Agent Actor/Turn projection and monotonic Runtime state;
- exact durable-history/live-event reconciliation;
- root context, cumulative Session usage and prompt-cache diagnostics;
- shared Shell/profile-PATH behavior for Terminal and Coder command tools;
- F140 configurable main-window close behavior;
- persisted Session, clipboard-image and attachment recovery;
- bounded Task/Agent scrolling and renderer state continuity.
- KodaX 0.7.77 split MCP/Extension/A2A integration configuration, SDK-backed Settings migration,
  and Settings source truth;
- SDK-recommended `kodax_manual` mechanism-topic preservation beneath Space desktop overlays.

It does not migrate Partner into the daemon, add a new Actor capability version, ship F137 document authoring, claim an OS sandbox, or claim signed/notarized installers.

## 7. Manual acceptance

### F140 close behavior

- [ ] Ask mode appears on main-window close.
- [ ] Cancel leaves the existing window usable.
- [ ] “Keep running” destroys the BrowserWindow and leaves a visible tray icon.
- [ ] Tray reopen creates a fresh usable window.
- [ ] Remembered keep-running is reflected in Preferences and affects the next close.
- [ ] Safe complete exit stops an idle daemon after Space disconnects.
- [ ] Active/queued/pending work or another client prevents daemon stop truthfully.
- [ ] A failed tray initialization cannot leave an invisible resident process.

Detailed journey: [FEATURE_140_v0.1.33_TEST_GUIDE.md](../test-guides/FEATURE_140_v0.1.33_TEST_GUIDE.md).

### Runtime and history

- [ ] A long restored Session shows no duplicate user/assistant Turn.
- [ ] Root transcript never renders child Agent text as the parent response.
- [ ] Agent/Task surfaces show canonical nested Actor state and remain scrollable.
- [ ] Compact preserves visible history while reducing only active model context.
- [ ] Resume/delete/close/reopen does not resurrect stale pending-send or activity state.

### Shell and attachments

- [ ] Auto Shell selects a supported platform shell.
- [ ] Explicit PowerShell/cmd choice affects new Terminal tabs and Coder command execution.
- [ ] Profile PATH exposes a version-manager-installed executable without copying secrets into the PTY environment.
- [ ] A pasted image persists with its normalized media type and survives Session reopen.
- [ ] Oversize or malformed clipboard input is rejected without writing outside the Session attachment directory.

## 8. Known and accepted boundaries

- Installers are unsigned; Windows SmartScreen and macOS Gatekeeper may prompt.
- Partner remains Space-owned embedded inline.
- F121 remains `InProgress` only for the explicit final human multi-client acceptance record.
- F132 remains an active polish item and is not represented as complete.
- F137 document authoring is planned for `v0.1.34`.
- A separate tray helper, OS-enforced native sandbox and general Connector/browser/automation surfaces are not part of this release.
- Unexecuted manual journeys remain unchecked after publication.

## 9. Publication sequence

1. Commit version, changelog, docs, manual and `kodax_manual` updates on `main`.
2. Run local automated gates and update this record with factual evidence.
3. Push `main`; wait for `ci` and `build` to pass.
4. Create annotated tag `v0.1.33` at the reviewed release commit and push the tag.
5. Wait for the four-platform `release` workflow and GitHub Release creation.
6. Verify release assets, updater manifests, published notes and latest-release status.
7. Record workflow URLs, asset digests and publication facts in a post-release documentation commit.
8. Push the evidence commit and wait for final `main` CI/build to pass.

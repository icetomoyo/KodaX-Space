## Release decision

v0.1.45 publishes the FEATURE_032 v2 inline ask-user cards and the KodaX
0.7.95, reconnect-recovery, idempotent-send, and history/feedback work already
present on the release source line. The npm Registry check on 2026-08-24
confirms KodaX 0.7.95 as `latest`. Release preparation changes only
version/dependency metadata, tests, one Runtime-host reconnect-timer ref fix,
and documentation; it does not change other system business logic.

The release includes:

- `ask_user_question` and guardrail prompts rendered as focused inline cards in
  the conversation stream, with a composer dock recall strip and 1-9/Enter/Esc
  keyboard control on the head card, replacing the full-screen modal;
- exact npm Registry KodaX 0.7.95 with `conversationHistory:2`,
  `runtimeExitSettlement:2`, and `sandboxRuntime:5` required before the
  corresponding lifecycle paths are used;
- recovery of admitted Runs by exact `runId` after a typed daemon reconnect,
  never replaying `runs.start()`, with Run-recovery reconnect timers kept
  scheduled so a pending wait cannot drain the host event loop;
- exactly one conversation bubble per idempotent `session.send` across idle and
  running Session crossings;
- stable live history replacement, topology-safe history negotiation, truthful
  Session activity/loading feedback, and bounded build/shutdown recovery;
- synchronized README files, Chinese user manual, docs hub, PRD/HLD, Feature
  List, capability ledger, Known Issues, usage guide, changelog, feature/test
  guides, and in-app `kodax_manual`.

## Release evidence

Local evidence on 2026-08-24:

- `npm run skills:check`: passed.
- `npm run test:release`: 44/44 passed.
- `npm run typecheck`: passed.
- `npm run lint`: passed.
- `SKIP_PTY_TESTS=1 npm test`: all workspace suites passed — IPC schema 44/44,
  Desktop 2824 tests (2811 passed, 13 PTY-skipped, 0 failed, 0 cancelled), and
  UI kit 312/312.
- `npm run build:smoke`: renderer and Electron main/preload/worker bundles
  passed.
- `node scripts/pack.mjs --win`: 0.1.45 installers built —
  `KodaX-Space-Setup-0.1.45.exe` 164,349,099 bytes (≈156.8 MB) and
  `KodaX-Space-Portable-0.1.45.exe` 164,139,140 bytes (≈156.6 MB), both under
  the 200 MB cap.
- `npm run smoke:pack` static audits: all passed (installer size and icon,
  asar integrity, native module placement, no test/mock leakage, packaged
  sqlite and node-pty probes).
- `node e2e/boot-smoke-packaged.mjs`: PASS — renderer ready in 10,416 ms,
  KodaX 0.7.95 Runtime ready in 32,130 ms after the deterministic hold.
- `node e2e/complete-exit-packaged.mjs`: PASS — two product exits clean with
  session history restored.

Host note (why the live packaged sandbox probe is deferred to CI): this
development host cannot confirm the sandbox broker's process-tree termination
inside the SDK's fixed 250 ms kill-confirmation budget. The KodaX 0.7.95
confirmation path runs `powershell.exe` with an inline `Add-Type` compile,
which costs ~300–345 ms here (measured with the SDK's own native snapshot
script), so each probe attempt returns "unknown", writes an `acl-poison`
recovery ticket, and blocks the next same-boot doctor check with
`acl_cleanup_unconfirmed` (plus one `acl_guards_missing` guard, whose
documented `kodax sandbox setup` remedy is gated behind the same ticket).
The residue is same-boot only: ACL state recovers clean
(`srt-win acl recover` reports `{"acesRevoked":0,"deadBrokers":0}`), no
processes leak, and both packaged product smokes above pass against the same
installers. A Windows reboot rotates the boot identity and clears the
blockers. The authoritative live-probe gate is the tag-time `release`
workflow, which runs the full `smoke:pack` (including the live sandbox probe)
on a fresh GitHub Windows runner where the 250 ms budget is met.

The unit-test rerun also covers the reconnect-timer ref fix: the Run-recovery
wait test previously left a pending promise that drained the Node event loop
and cancelled 65 sibling tests; after the fix the same suite runs
2811/2811 non-skipped with zero cancellations.

GitHub evidence is recorded only after the corresponding exact commit succeeds.
The tag and public GitHub Release must not be created while any required pre-tag
gate is pending or failed.

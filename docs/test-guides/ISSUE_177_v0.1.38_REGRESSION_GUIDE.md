# Issue 177 v0.1.38 - 人工回归测试指导

## 功能概述

**功能名称**: 历史恢复中的 Provider retry 去重与 compact notice 排序
**版本**: v0.1.38 release maintenance
**测试日期**: 2026-08-08
**测试人员**: 待填写

验证历史页、实时事件和 local notice 合并后，每段内容只出现一次并保持真实时间顺序。

## 测试环境

### 前置条件

- 使用包含本修复的 Windows 构建；保留一份开发构建用于注入 Provider 断流。
- 准备一个可触发 `/compact` 的长会话，以及一个可在文本流中断开网络的测试 Provider。
- 打开开发者日志，确认 canonical Session history 本身没有重复或乱序。

### 环境要求

- Windows 10/11，正常网络与可控弱网各一次。
- 同时验证开发模式和 `out/win-unpacked` 打包应用。

## 测试用例

### TC-001: 中途断流重试后只显示最终答案

**优先级**: 高
**类型**: 正向测试

**前置条件**:

- Provider 支持在已输出部分文本后触发 `stable_boundary_retry`。

**测试步骤**:

1. 发送一个会持续输出的请求。
2. 在出现部分文本后中断连接，并等待自动重试成功及会话结束。
3. 切换到另一会话再返回，然后按 Ctrl+R。
4. 继续产生足够多的新 turn，使该恢复 turn 移出 newest history window，再重新打开会话。

**预期效果**:

- [ ] 仅显示成功重试产生的最终答案，刷新前后内容一致。
- [ ] 该 turn 移出 newest window 后，失败草稿和 live 副本不会在 transcript 尾部复活。
- [ ] Runtime 恢复状态仍可见，日志仍包含 `provider_recovery` 诊断事件。

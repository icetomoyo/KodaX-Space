This is the Space-side source of truth for SDK-dependent capability planning. A capability is supported only when a public contract exists and Space has verified/consumed it. A KodaX design document or version number alone is not support.

## Status model

| Contract status | Meaning                                                                                                          |
| --------------- | ---------------------------------------------------------------------------------------------------------------- |
| `published`     | Public export/event/DTO exists in an installable SDK baseline.                                                   |
| `candidate`     | Public contract exists in the exact installable tarball under verification but is not yet the registry baseline. |
| `planned`       | KodaX has an active design but no published compatible contract.                                                 |
| `reviewed-out`  | KodaX explicitly removed/deferred the proposed primitive.                                                        |

| Space adoption | Meaning                                                               |
| -------------- | --------------------------------------------------------------------- |
| `supported`    | Contract and Space UX/runtime path are implemented and verified.      |
| `partial`      | A useful slice exists, but the intended semantics are incomplete.     |
| `planned`      | Space has an active feature with an explicit gate.                    |
| `watchlist`    | No version commitment; reopen only when the stated gate passes.       |
| `not-needed`   | KodaX already owns the capability or no desktop surface is justified. |

## Runtime and session capabilities

### Current source candidate: KodaX 0.7.96-alpha.2

The source tree pins the exact published prerelease in both manifests and the
npm lockfile. SDK startup, daemon admission, and connected Runtime checks require
`sandboxRuntime:6`; the standalone facade must also report
`trustedTextAuthority:host-transaction`,
`windowsShellAuthority:native-token-job-v2`, and
`commandLifetimeFilesystemLease:false`. The release dependency gate requires the
complete universal native bundle. Electron packaging unpacks the whole
`dist/native` directory, and packaged smoke validates each manifest-pinned file
before running the real sandbox path. Space remains package version 0.1.45 until
a separate release preparation changes its version. Alpha.2 restores the Windows
lifecycle PowerShell executable resolver missing from alpha.1; Space consumes the
integrity-pinned Registry bytes without patching them.

Provider adoption includes the built-in DeepSeek vision-only
`deepseek-v4-flash-vision-exp` route and multimodal `glm-5.3-flash` on `zhipu`,
`zhipu-coding`, and `zai-coding`. The GLM route advertises a 1,000,000-token
context window, 131,072-token maximum output, and mandatory thinking; existing
provider defaults remain unchanged. Space custom OpenAI/Anthropic-compatible
providers expose the SDK's optional `imageInput` flag through the form, bounded
IPC, persistence, shared KodaX config, and live Runtime catalog. It remains an
explicit opt-in because Space cannot prove that a compatible upstream model
actually supports vision.

The installed README, Chinese README, changelog, and shipped public guides match
the `v0.7.96-alpha.2` source tag byte-for-byte. The npm package does not include
every repository document referenced by their relative links (including the
release checklist and advanced custom-provider guide), so those links require
the tagged source repository; this is an upstream documentation-packaging
limitation, not a mutation of the integrity-pinned runtime bytes.

Space also consumes FEATURE_296's structured failure contract. The host keeps
the SDK-owned `safeMessage`, stable `providerErrorCode`, bounded support IDs,
retry delay, and local capacity `required` / `available` token facts through
Runtime status/events and validated IPC. Conversation errors expose those facts
without raw provider bodies or credentials. Unknown future provider codes stay
displayable through a bounded default path, and `context_capacity_exceeded` is
non-retriable in Space because KodaX has already exhausted its capacity-debt,
compaction, reserve-shrink, and oversized-input recovery ladder before emitting
that terminal fact.

Alpha.2 also publishes optional credential-safe `RuntimeFailureDetail` facts on
terminal/settlement events, Run result/status, and Session diagnostics. Space
projects the same allowlisted structure through its bounded Runtime and Session
DTOs, renders the SDK-owned `safeMessage`, and chooses recovery actions from the
stable `providerErrorCode`. The error notice exposes only bounded code, stage,
Run/request identity, status, retry, and context-capacity facts; it never accepts
raw Provider response text, headers, URLs, prompts, paths, stacks, or errors.
Older daemons remain compatible through the existing optional `failureKind` and
generic terminal-message path.

### v0.1.45 published KodaX 0.7.95 baseline

The v0.1.45 release pins exact Registry KodaX `0.7.95` in both
manifests and lockfiles. It requires `conversationHistory:2`, recovers an admitted
Run only from typed reconnectable transport loss by querying the same `runId`, and
preserves the SDK's credential-safe `failureKind` without exposing provider text.
All enabled Skills remain available to explicit `/skill` invocation; model
visibility continues to honor `disable-model-invocation` independently. Space also
requires `runtimeExitSettlement:2` and `sandboxRuntime:5`, retries the SDK's
same-boot transient owner verification until it converges or app shutdown cancels
the wait, and verifies that explicit-Skill durable history contains only the raw query.
The published Space v0.1.44 baseline below remains historical.

### v0.1.44 published KodaX 0.7.93 baseline

The v0.1.44 release pins the exact npm Registry KodaX `0.7.93` package in both
manifests and the lockfile. Its installed bytes match the official Registry
tarball and retain `runtimeExitSettlement:1`, `sandboxRuntime:4`, and
`crashOutcomeModel:2`. Settlement may recover multiple Windows ACL markers only
after a changed boot and a machine-lock recheck prove that every identity is
canonical and non-current. Mixed, missing, corrupt, current-boot, or concurrent
owner state remains blocked; the recovery path does not enter Setup or UAC.

### v0.1.43 published KodaX 0.7.92 baseline

That historical release uses the exact npm Registry KodaX `0.7.92` package and SHA512
recorded in its release-readiness record. The root and Desktop manifests,
lockfile, installed package and packaged ASAR must agree with the official
Registry URL and bytes. KodaX `0.7.92`
is the published Space v0.1.43 artifact baseline.
The published Space v0.1.37 through v0.1.42 artifacts remain historical evidence
for their respective KodaX baselines; they are not rewritten to claim the
newer dependency. The v0.1.41 public release remains qualified against KodaX 0.7.87;
the v0.1.42 source snapshot additionally requires `actorSettlementConvergence:2` from the installed SDK and
connected Runtime while retaining its historical `sandboxRuntime:3` gate. The
v0.1.43 release requires `sandboxRuntime:4` and `crashOutcomeModel:2` before
daemon startup and after connection.
Space keeps a bounded active-Session input-admission boundary around send,
interrupt, after-turn, Session switching, draft recovery, and history
revalidation, and extends the same identity fence to multi-Session recovery
and complete-exit recovery. Exact `runId`/`turnId`, source revisions, cursors,
and Session identity remain the authoritative ownership facts; message content
and stale snapshots are never used to manufacture completion.

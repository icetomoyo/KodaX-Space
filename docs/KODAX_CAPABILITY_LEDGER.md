## Status model

| Contract status | Meaning                                                                                                          |
| --------------- | ---------------------------------------------------------------------------------------------------------------- |
| `published`     | Public export/event/DTO exists in an installable SDK baseline.                                                   |
| `candidate`     | Public contract exists in the exact installable tarball under verification but is not yet the registry baseline. |
| `planned`       | KodaX has an active design but no published compatible contract.                                                 |
| `reviewed-out`  | KodaX explicitly removed/deferred the proposed primitive.                                                        |

| Space adoption | Meaning                                                               |
| -------------- | --------------------------------------------------------------------- |
| `supported`    | Contract and Space UX/runtime path are implemented and verified.      |
| `partial`      | A useful slice exists, but the intended semantics are incomplete.     |
| `planned`      | Space has an active feature with an explicit gate.                    |
| `watchlist`    | No version commitment; reopen only when the stated gate passes.       |
| `not-needed`   | KodaX already owns the capability or no desktop surface is justified. |

## Runtime and session capabilities

### v0.1.43 source and published KodaX 0.7.92 baseline

The current source uses the exact npm Registry KodaX `0.7.92` package and SHA512
recorded above. The root and Desktop manifests, lockfile, installed package and
packaged ASAR must agree with the official Registry URL and bytes. KodaX `0.7.92`
is the current published SDK baseline.
The published Space v0.1.37 through v0.1.39 artifacts remain historical evidence
for their respective KodaX baselines; they are not rewritten to claim the
newer dependency. The v0.1.41 public release remains qualified against KodaX 0.7.87;
the v0.1.42 release additionally requires `actorSettlementConvergence:2` from the installed SDK and
connected Runtime while retaining its historical `sandboxRuntime:3` gate. The
v0.1.43 source requires `sandboxRuntime:4` and `crashOutcomeModel:2` before
daemon startup and after connection.
Space keeps a bounded active-Session input-admission boundary around send,
interrupt, after-turn, Session switching, draft recovery, and history
revalidation, and extends the same identity fence to multi-Session recovery
and complete-exit recovery. Exact `runId`/`turnId`, source revisions, cursors,
and Session identity remain the authoritative ownership facts; message content
and stale snapshots are never used to manufacture completion.
